25 · 事件过滤、焦点与键盘：保留正常交互

前置：第 24 章。目标：理解事件传播，给输入框增加行为且不吞掉正常操作。

四个观察层次

用户按键 → 焦点控件收到事件 → 控件处理 → 可能发出更高层信号。提交表单优先连接 returnPressed；菜单命令优先 QAction 的 shortcut；只有这些语义信号不够时才重写 keyPressEvent 或安装 eventFilter。

鼠标点击一个控件不代表任意自定义 QWidget 都能获得键盘焦点。自定义键盘控件需要合理的 focusPolicy；Tab 顺序需要按阅读顺序检查。禁用控件通常不能交互，隐藏控件也不应成为可见流程的必需步骤。

只拦截自己处理的事件

下面是 QWidget 子类中的成员函数片段，search_ 是成员 QLineEdit，构造时已调用 search_->installEventFilter(this)：

bool eventFilter(QObject *watched, QEvent *event) override {
    if (watched == search_ && event->type() == QEvent::KeyPress) {
        auto *key = static_cast<QKeyEvent *>(event);
        if (key->key() == Qt::Key_Escape) {
            search_->clear();
            return true;  // 本次 Esc 已经处理
        }
    }
    return QWidget::eventFilter(watched, event);
}

先检查事件类型，才把基类指针转换成 QKeyEvent。对所有事件返回 true，会使输入、绘图、焦点等功能失效。过滤器和目标对象需要合适的线程归属，不借过滤器跨线程操作界面。

高频输入不要直接触发昂贵工作

用户连续输入“Qt 教程”，不一定希望执行四次数据库搜索。创建 singleShot 的 250ms QTimer，每次 textChanged 重新 start；timeout 时读取当前文本发起查询。这叫防抖：连续输入暂不执行，停顿后执行一次。它与“每隔固定时间最多执行一次”的节流不同。

防抖只减少请求，不保证返回顺序正确。异步搜索还需要第 28 章的请求序号；用户清空输入时应立即恢复默认显示，或明确告知正在查询。

验收顺序

在 03_form 加搜索输入，依次验证普通输入、中文输入法、Backspace、方向键、Tab、Esc。Esc 只清空搜索框，其他按键行为保持正常。长按按键会有自动重复事件，若动作只允许执行一次需检查 isAutoRepeat。

练习答案要点：过滤范围限定到目标和特定事件；未处理情况交给基类；对于按钮命令先考虑 QAction 或快捷键。无法在当前环境测试输入法时记录限制，不据 ASCII 输入推断全部文字输入正确。
