前置：第 08、12 章。目标：创建第二个窗口，并正确处理取消和重复打开。

先选择窗口关系

类型 适合场景 关键问题
主窗口 主工具与菜单 谁是 centralWidget
模态对话框 当前操作需要先做决定 取消是否保持原数据
非模态工具窗 查找、帮助、持续观察 关闭后是隐藏还是销毁

模态限制用户与其他窗口交互，不等于把工作放到后台。exec() 会建立嵌套事件循环，代码看起来像同步等待，但其他事件仍可能发生；新代码优先考虑 open() 配合 finished 或 accepted 信号。

一次性对话框的安全写法

以下片段放在 QWidget 子类成员函数中，this 是拥有者，已包含 QtWidgets：

auto *dialog = new QDialog(this);
dialog->setWindowTitle(tr("修改姓名"));
dialog->setAttribute(Qt::WA_DeleteOnClose);
auto *layout = new QVBoxLayout(dialog);
auto *edit = new QLineEdit(dialog);
auto *buttons = new QDialogButtonBox(
    QDialogButtonBox::Ok | QDialogButtonBox::Cancel, dialog);
layout->addWidget(edit);
layout->addWidget(buttons);
connect(buttons, &QDialogButtonBox::accepted, dialog, &QDialog::accept);
connect(buttons, &QDialogButtonBox::rejected, dialog, &QDialog::reject);
connect(dialog, &QDialog::accepted, this, [this, edit] {
    setWindowTitle(edit->text().trimmed());
});
dialog->open();

数据在 accepted 时才提交，Cancel 不改变主窗口。真实表单应先验证再 accept；上例只用于理解窗口寿命和信号顺序，不代表完整的姓名业务规则。

两个常见错误

在函数中创建局部 QDialog dialog; dialog.open(); 后立即返回，对话框随局部变量析构，不能继续显示。反过来，不断 new 顶层窗口却没有父对象、也不设置关闭后删除，会残留隐藏对象。

需要始终只开一个查找窗时，将其保存在 QPointer 成员中；存在则 show、raise、activateWindow，不存在再创建。QPointer 在销毁后清空，但隐藏不会清空。应先决定“复用隐藏窗口”还是“关闭即删除”，再选择逻辑。

动手与验收

给 03_form 增加一个“修改姓名”按钮。先允许连续打开多个窗口，观察各自状态；再实现单实例。测试确定、Cancel、右上角关闭、主窗口先关闭四条路径。

参考答案要点：临时输入放在对话框内，业务数据在确认后改变；引用捕获的局部变量不能随函数返回而消失。验收：Cancel 保持原姓名，连续打开不产生悬空访问，主窗口关闭后子窗口正确清理。

对话框与主窗口：参数、结果与时机

QDialog::open()

  • 参数怎样填：无参数。
  • 作用与返回结果：异步打开模态对话框，返回 void，调用者继续执行。
  • 调用时机与易错点：对话框不能是马上离开作用域的局部对象；通过 accepted/rejected 接结果。

QDialog::accept() / reject()

  • 参数怎样填：无参数。
  • 作用与返回结果：设置对话框结果并结束交互。
  • 调用时机与易错点：accept 前应完成验证；Cancel 不应已写入真实业务数据。

setAttribute(Qt::WA_DeleteOnClose)

  • 参数怎样填：属性枚举以及可选 bool。
  • 作用与返回结果：关闭后安排删除窗口。
  • 调用时机与易错点：成员观察指针可能失效；使用 QPointer 或明确复用策略。

QMainWindow::setCentralWidget(widget)

  • 参数怎样填：中央控件指针。
  • 作用与返回结果：将控件放进主窗口中心并由主窗口拥有。
  • 调用时机与易错点：不要直接对 QMainWindow setLayout，它已有自己的结构。

menuBar()->addMenu(title)

  • 参数怎样填：菜单标题。
  • 作用与返回结果：返回新建 QMenu 指针。
  • 调用时机与易错点：菜单属于界面结构，不把 SQL 或文件业务写进菜单数据中。

QMenu::addAction(text)

  • 参数怎样填：动作标题。
  • 作用与返回结果：返回 QAction 指针，常连接 triggered。
  • 调用时机与易错点：QAction 是命令模型，可由菜单和工具栏共同使用，不是 QPushButton。

QAction::setShortcut(sequence)

  • 参数怎样填：如 QKeySequence::Save。
  • 作用与返回结果：设置命令快捷键。
  • 调用时机与易错点：优先使用平台标准键序列；不要和输入控件必要编辑快捷键冲突。

QFileDialog::getOpenFileName(...) / getSaveFileName(...)

  • 参数怎样填：父窗口、标题、初始目录和过滤器等。
  • 作用与返回结果：返回选中路径 QString，取消通常返回空字符串。
  • 调用时机与易错点：选中路径不代表已经读取或保存成功；空路径不覆盖当前文档状态。

QMessageBox::question(...)

  • 参数怎样填：父窗口、标题、内容、候选按钮和默认按钮。
  • 作用与返回结果：返回用户选择的 StandardButton。
  • 调用时机与易错点：要分别处理 Save、Discard、Cancel；Save 之后还要检查真正的保存结果。

QCloseEvent::accept() / ignore()

  • 参数怎样填：无参数。
  • 作用与返回结果：允许本次关闭或保持窗口打开。
  • 调用时机与易错点：文件对话框取消或写入失败应 ignore，不能仅看用户曾按过 Save。

Ui::Form::setupUi(widget)

  • 参数怎样填：uic 生成的函数，传要安装界面的控件。
  • 作用与返回结果：创建 ui 中定义的控件、布局和属性。
  • 调用时机与易错点：不是 Qt 通用类的任意成员；不要手工编辑生成的 ui_*.h。
