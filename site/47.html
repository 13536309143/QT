47 · 练习参考答案与最终验收清单

参考思路

计数器复位：把 count_ 改为 0，发 countChanged(0)，不要只改标签。表单验证：先 trimmed，再检查非空与确认状态；验证失败保留输入。模型插行：计算旧行数，beginInsertRows({}, row, row)，append，endInsertRows。代理删除：mapToSource，再读主键，用参数绑定 DELETE。

JSON 校验：先检查 QJsonParseError，再检查 isObject/isArray，逐字段类型验证；不要用默认值吞掉损坏。编辑器关闭：Cancel 返回 false，Save 返回 saveFile 的真实结果，Discard 才直接放行。线程取消：设置中断标记，循环检查，结束后 quit；窗口退出等待后台释放。

关键自测问题

  1. QApplication 为什么在 QWidget 前构造？事件循环忙时为什么界面卡住？
  2. 一个 QObject 有父对象，再给两个不相关所有者分别 delete 会怎样？
  3. lambda 的上下文对象存活是否保证所有引用捕获都有效？
  4. QThread 对象的线程归属和其管理的线程为何不同？
  5. 为什么 SQL 绑定比 arg 拼接可靠？筛选后为什么要映射索引？
  6. 为什么 windeployqt 成功不等于在另一台电脑一定能启动？
  7. QML 属性没有 NOTIFY 时，C++ 状态改变后绑定为什么可能不更新？

发布前手工验收

  • 从 README 全新构建，Qt 版本为 6.8.3，测试通过。
  • 首个窗口、Designer、资源、QML 都可启动。
  • 编辑器保存/取消/失败、中文路径均检查过。
  • 线程开始、取消、再次开始、运行中关闭不崩溃。
  • 本地 HTTP 200/404/服务关闭均处理并恢复按钮。
  • TaskDesk 重启数据保留，排序和搜索后修改对象正确。
  • dist 在独立环境测试；未测试的平台明确标注。
  • 暂存文件中无 SDK、个人数据、构建缓存、访问令牌。

继续学习的方法

把一个例子合上后从空白文件重写，是检验理解的好办法。遇到问题先做最小复现，再查对应版本的官方类文档。每章用自己的话写“为什么这样设计”，比背诵类名更有助于独立开发。
