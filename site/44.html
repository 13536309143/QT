44 · 综合项目 TaskDesk：分阶段扩展作业

第一阶段：让核心功能可靠

通读现有测试，增加 trim 后保存的断言。调整输入框最大长度时，仓储规则也要保持一致。为查询失败提供重试入口。确认列目前显示 1/0，先将显示与存储分离，再改成勾选图标，避免改变数据库值的意义。

第二阶段：优先级和截止日期

为数据库加入 schema_version，设计从 v1 到 v2 的迁移：开事务 → ALTER TABLE 添加 priority → 初始化旧记录 → 更新版本 → commit。未知更高版本不要自动降级。优先级范围在数据库 CHECK 与仓储验证中一致。

界面上用 QComboBox 编辑优先级、QDateEdit 编辑日期。日期为空的含义要明确，例如“无截止日期”，不要偷偷用今天代替。测试覆盖旧文件升级、迁移失败回滚以及截止日期排序。

第三阶段：导入导出

JSON 顶层包含 formatVersion 与 tasks 数组，导入前校验类型和长度。重复任务如何处理需要明确策略：追加、合并或替换，界面先让用户预览数量。替换是破坏性操作，应确认并备份；不要把读取失败解释为“空任务列表”再覆盖原数据库。

第四阶段：分页和异步

生成几万条测试数据，用 QElapsedTimer 测量启动和搜索；把查询过滤下推 SQL，改用分页。若后台查库，在工作线程新建命名连接，不共享 GUI 连接。结果携带请求序号，较旧请求返回时丢弃，避免快速搜索显示旧结果。
