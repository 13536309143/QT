前置：第 21、22 章。目标：让显示、编辑和业务标识各自清楚。

同一个单元格可以有多个角色

DisplayRole 决定显示文字，EditRole 提供编辑值，CheckStateRole 表示勾选状态，UserRole 及之后的角色可携带业务标识。以优先级为例：显示“高”，编辑值是整数 2，数据库主键另存，不从“高”推断行身份。

模型不只负责 data。rowCount/columnCount 定义结构；flags 决定可编辑、可选择或可勾选；setData 验证写入，成功后发 dataChanged。只加 ItemIsEditable 却不实现 setData，编辑器看似能输入但数据不会真正保存。

通知顺序是协议

操作 正确顺序
改已有值 校验 → 修改 → dataChanged
插入行 beginInsertRows → 修改容器 → endInsertRows
删除行 beginRemoveRows → 修改容器 → endRemoveRows
全量替换 beginResetModel → 替换 → endResetModel

begin 调用时视图还应能看到旧结构。不要修改完容器才 begin，也不要用 reset 代替每次小修改，否则选择和持久索引可能丢失。QModelIndex 是模型中的位置，不是永远不变的业务主键；模型 reset 后不能继续使用旧索引。

委托的四步

继承 QStyledItemDelegate，createEditor 创建 QComboBox，setEditorData 将 EditRole 的编号放进编辑器，setModelData 把 currentData 提交给模型，必要时 updateEditorGeometry 放置编辑器。先在自定义模型中验证取值范围，不能只依赖控件约束。

提交接口返回 false 时保留原值并反馈；对于 TaskDesk，更新还要通过仓储执行 SQL，再刷新模型。不要把普通内存模型的 setData 片段直接搬到只读 QSqlQueryModel，假设它会自动写回数据库。

实验路线

  1. 以 06_model 为起点，为优先级列提供整数 EditRole。
  2. 加一个只负责优先级的下拉委托，不把整张表改成 setIndexWidget。
  3. 对非法值 -1、100 拒绝写入，返回 false。
  4. 连接 dataChanged 记录修改的行列，重复设置相同值时不制造无意义变化。
  5. 加 QAbstractItemModelTester 运行结构检查，再进行排序、过滤后修改。

验收：显示可翻译而业务编号不变；取消编辑保持旧值；删除操作先 mapToSource 再读取主键。模型只能在其所属线程安全操作；后台结果应作为数据传回模型线程再应用。

参考：模型接口、模型测试器。

模型、代理与索引：参数、结果与时机

rowCount(parent) / columnCount(parent)

  • 参数怎样填：父索引，平面表格通常只接受无效父索引。
  • 作用与返回结果：返回该父节点下的行列数 int。
  • 调用时机与易错点：对于有效父索引，简单平面模型通常返回 0，避免被误判为树。

data(index, role)

  • 参数怎样填：索引与所需角色，如 DisplayRole。
  • 作用与返回结果：返回 QVariant；不支持角色或非法位置返回空值。
  • 调用时机与易错点：显示、编辑、排序可读取不同角色，不能把所有角色都当字符串。

headerData(section, orientation, role)

  • 参数怎样填：表头位置、方向和角色。
  • 作用与返回结果：返回对应表头 QVariant。
  • 调用时机与易错点：只处理自定义情形，其他请求交回基类，避免破坏默认行号。

flags(index)

  • 参数怎样填：索引。
  • 作用与返回结果：返回可选、启用、可编辑等标志位。
  • 调用时机与易错点：单独增加 ItemIsEditable 不会自动实现保存，还需 setData。

setData(index, value, role)

  • 参数怎样填：目标、候选数据和编辑角色。
  • 作用与返回结果：返回 bool；成功更新数据后发 dataChanged。
  • 调用时机与易错点：先校验范围与类型，失败不改原数据；不要仅刷新文字而不更新模型。

dataChanged(topLeft, bottomRight, roles)

  • 参数怎样填：受影响的矩形范围和角色列表。
  • 作用与返回结果：信号通知视图重新读取对应数据。
  • 调用时机与易错点：不是让数据自动改变；需先更新内部状态，再发通知。

beginInsertRows(parent, first, last) / endInsertRows()

  • 参数怎样填：插入范围，first/last 包括两端。
  • 作用与返回结果：在修改容器前后成对通知视图。
  • 调用时机与易错点：begin 在旧结构仍有效时调用；不能修改完才通知开始。

setSourceModel(model) / setModel(model)

  • 参数怎样填：分别属于代理模型和视图。
  • 作用与返回结果：连接源数据到代理、代理到视图。
  • 调用时机与易错点：视图不因此任意接管模型所有权，应明确 parent 或普通对象寿命。

setFilterKeyColumn(column)

  • 参数怎样填：待筛选的列号；-1 有其多列语义。
  • 作用与返回结果：设置筛选列。
  • 调用时机与易错点：本例任务标题在第 0 列，选错列会让查询结果看似丢失。

setFilterFixedString(text)

  • 参数怎样填：用户筛选文字。
  • 作用与返回结果：按固定字符串规则过滤。
  • 调用时机与易错点：与正则表达式筛选不同，用户输入正则符号不会自动成为模式。

mapToSource(proxyIndex)

  • 参数怎样填：当前代理索引。
  • 作用与返回结果：返回源模型索引。
  • 调用时机与易错点：删除和更新先检查有效性，再读稳定主键；代理行号不是数据库 id。

currentIndex() / isValid()

  • 参数怎样填：视图取当前项，索引检查有效性。
  • 作用与返回结果：返回 QModelIndex / bool。
  • 调用时机与易错点：没有选中或模型已 reset 时旧索引可能无效，不能继续读取旧行。

setSortingEnabled(true)

  • 参数怎样填：视图 bool。
  • 作用与返回结果：允许表头触发排序。
  • 调用时机与易错点：字典序的字符串“10”可能先于“2”，数值排序要提供合适类型或角色。
