40 · Windows 部署：让程序离开开发机

SDK 与应用分发包是两回事

SDK 包含头文件、导入库和开发工具，供编译使用；dist 包含 exe 和运行需要的 DLL、插件与 QML 模块，供用户运行。不能把整个 sdk 上传到 GitHub，也不能只发一个依赖动态 Qt 的 exe。

使用项目脚本：

scripts\deploy.cmd 01_hello
scripts\deploy.cmd taskdesk
scripts\deploy.cmd 13_quick

脚本从 Release 输出复制指定程序，再调用同一 SDK 的 windeployqt；Quick 应额外传入 --qmldir 扫描 QML 源码。SQL 程序要检查 sqldrivers/qsqlite.dll，Widgets 程序需要 platforms/qwindows.dll。编译器运行库也应由合法方式分发。脚本会将 vc_redist.x64.exe 放入分发目录，目标机器缺少 MSVC 运行库时先安装，再运行应用。

干净环境验证

在没有 Qt PATH 的终端或干净 Windows 虚拟机运行 dist 程序，检查打开、保存、中文路径、数据库和关闭流程。使用独立分发目录避免“开发机 PATH 帮你找到缺失依赖”产生假成功。图形驱动、TLS 后端和 Windows 系统版本也可能影响运行，不能仅凭 windeployqt 返回成功就宣称适配所有电脑。

Debug 与 Release DLL 不混用，MSVC 与 MinGW 不混用，不同 Qt 版本尽量不混用。需要安装包时再选择合适工具，本课程先提供可检查的目录式分发。

练习：分别部署 hello 和 Quick，比较目录差异。验收：分发包可以从另一个目录启动；即使原源码不在也能找到静态资源。发布前核对实际依赖模块许可，并提供对应通知和合规材料；仓库自己的 LICENSE 不会替代第三方依赖许可。 参考：Windows 部署、Qt 许可说明。
