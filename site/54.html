54 · Qt 与 Vulkan 环境：头文件、Loader、驱动与实例

一、先分清四个安装层次

Vulkan 头文件让编译器认识 VkBuffer 等类型；Loader 在运行时装载驱动入口；显卡驱动提供设备实现；SDK 还提供验证层、shader 工具和诊断工具。拥有 vulkan.h 不意味着运行时一定能找到 GPU；有 vulkan-1.dll 也不意味着验证层或 shader 编译工具已安装。

Qt 6.8 的 QVulkanInstance、QVulkanWindow 位于 Qt Gui。课程已有 Qt Gui，但应用编译直接使用 Vulkan 结构体时仍需 Vulkan 头文件。本项目将 Vulkan 构建设为可选，避免没有 SDK 的初学者连 Widgets 都无法构建。

二、构建示例的两条路线

完整开发推荐安装适合本机的 Vulkan SDK，再在新的终端确认 VULKAN_SDK，检查 Include、Bin 和工具。SDK 版本与驱动支持不是一回事，不因安装了最新 SDK 就请求最新 API 特性。

仅编译清屏示例可以使用固定版本的 Khronos Vulkan-Headers。当前本地将它放到被忽略的 .tools/vulkan-headers，版本 vulkan-sdk-1.3.290.0。它不提供验证层、运行时或 glslc，所以不能把这个轻量编译环境写成完整 SDK。

# 从仓库根目录执行；需要联网，仅首次获取头文件
git clone --depth 1 --branch vulkan-sdk-1.3.290.0 https://github.com/KhronosGroup/Vulkan-Headers.git .tools/vulkan-headers

如果目录已存在，不重复 clone；先核对版本。使用项目开发者环境配置 CMake 的 COURSE_BUILD_VULKAN=ON，具体一键命令见 scripts/build-graphics.cmd。未启用时 18_vulkan 不会生成 exe。

三、实例在设备之前

QVulkanInstance 管理应用级 Vulkan instance。setApiVersion(QVersionNumber(1,0,0)) 提出基线请求；supportedLayers 返回可用层列表；setLayers 在 create 前指定可选验证层；create 返回 bool，失败读取 errorCode。

本例只有用户显式加 --validation 才要求 VK_LAYER_KHRONOS_validation。若该层不存在就明确失败，不静默假装验证已开启。生产版本也不应强制要求目标用户安装开发验证层。

四、创建顺序与销毁顺序

先创建 QGuiApplication，再创建 instance，再创建窗口并 setVulkanInstance。窗口和渲染器依赖 instance，必须比它先销毁。本例把 instance 声明在窗口之前，使局部对象逆序析构满足这一点；不要把局部 instance 的地址交给一个会存活更久的堆窗口。

create 成功只证明实例建立，设备、surface、交换链仍可能失败。show 后让 Qt 完成窗口暴露与初始化，再观察 QVulkanWindow::isValid。不能在刚构造窗口时就把尚未初始化的设备 handle 当作有效对象使用。

五、第一次检查失败按层定位

编译时找不到 vulkan.h：检查 include 路径；实例失败：检查 Loader 与实例要求；无设备或窗口无效：检查驱动、设备选择与 surface；验证层不可用：检查 SDK 的层发现配置。不要把所有失败都归因于“Qt 不支持 Vulkan”。

运行 scripts\run.cmd 18_vulkan --self-test。自检只保证窗口设备有效且至少记录一帧，不等价于已经运行 Khronos 验证层或证明所有同步正确。下一章解释这帧命令怎样交给 Qt。
