从用户点击到状态改变

信号表示发生了某件事，槽或 lambda 响应它。以计数器为例：按钮 clicked → 计数加一 → 自定义 countChanged → 标签更新。让状态变化发信号，比把所有控件更新硬塞到点击函数里更容易扩展。

connect(button, &QPushButton::clicked, this, [this] {
    emit countChanged(++count_);
});

emit 只是表达“发出信号”的可读性标记。信号由 moc 提供实现，不要自己为同一个信号写函数体。新式函数指针连接能做编译期类型检查，初学时优先使用，不使用旧字符串 SIGNAL/SLOT 语法。

连接类型

AutoConnection 在发射时依据接收对象的线程归属选择直接或排队执行。同线程通常立即调用；跨线程通常排队到接收线程。DirectConnection 在发射线程执行槽，因此不能把后台信号强制 Direct 到界面更新槽。QueuedConnection 需要接收线程处理事件，参数必须可复制并且 Qt 元类型系统知道相应类型。避免把指向短生命周期缓冲区的裸指针作为排队消息。

常见问题

重复调用 connect 会导致一次点击执行多次。构造时集中连接，或保存 QMetaObject::Connection 以便精确断开。UniqueConnection 不能通用于 lambda 去重。信号槽参数不必完全一样，接收端可以不接收信号的尾部参数，但已接收的参数类型应兼容。

操作：运行 02_counter，增加“重置”按钮；重置应先改变 count_，再发同一个 countChanged。验收：加三次后重置显示 0，再加一次显示 1；不要只修改标签却忘了内部状态。 参考：信号槽。

配套完整源码

在根工程构建本章目标：02_counter。以下是仓库内同一份文件，修改请到 examples 目录。

main.cpp

#include <QtWidgets>
class Counter final : public QWidget {
    Q_OBJECT
public:
    Counter() {
        auto *layout = new QVBoxLayout(this);
        auto *value = new QLabel("0", this);
        auto *button = new QPushButton(QStringLiteral("加一"), this);
        layout->addWidget(value); layout->addWidget(button);
        // this 是连接上下文：窗口销毁后连接自动失效。
        connect(button, &QPushButton::clicked, this, [this] { emit countChanged(++count_); });
        connect(this, &Counter::countChanged, value, [value](int n) { value->setText(QString::number(n)); });
        resize(320,180);
    }
signals:
    void countChanged(int count);
private:
    int count_ = 0;
};
int main(int argc,char **argv) {
    QApplication app(argc,argv); Counter w; w.show();
    if(app.arguments().contains("--smoke")) QTimer::singleShot(150,&app,&QCoreApplication::quit);
    return app.exec();
}
// Q_OBJECT 在 cpp 中定义时，AUTOMOC 需要这一行。
#include "main.moc"

把一次 connect 读成一句话

connect(sender, &Sender::changed, receiver, &Receiver::updateValue) 表示 sender 通知 changed 时，让 receiver 处理 updateValue。槽参数与信号参数必须兼容；槽可以接收较少参数，但不能要求信号没有提供的额外参数。emit 只是标记发出信号，并不会自动把执行搬到后台。

AutoConnection 在发出信号时，根据当前执行线程与接收对象线程归属选择直接调用或排队处理。直接连接中的槽通常在 emit 返回前执行；队列连接依赖接收线程处理事件。不要为了“更快”对跨线程 GUI 操作强制 DirectConnection。

两个故障实验

  1. 把同一条 connect 在构造函数中写两次，点击一次，观察槽执行两次。真正修复是只建立一次连接，或保存 QMetaObject::Connection 并在重建前断开。
  2. 把 connect 放在“每次刷新”函数里，连续刷新五次，观察重复通知；再把连接移回初始化阶段。

Qt::UniqueConnection 适用于可识别的成员函数连接，不能依赖它给任意 lambda 去重。保存连接句柄后可 QObject::disconnect(connection)；发送者或接收上下文销毁时，相关连接也会自动断开。

验收：能解释点击一次执行多次、信号发出却未收到、对象已经销毁三类问题；带 lambda 的 connect 提供合适上下文，并检查每个被捕获对象的实际寿命。

对象树与连接：参数、结果与时机

QObject::connect(sender, signal, context, functor)

  • 参数怎样填：发送者、类型安全信号指针、上下文、lambda。
  • 作用与返回结果：返回 QMetaObject::Connection；建立以后发生的通知关系。
  • 调用时机与易错点：不是调用槽一次；重复建立会重复执行。上下文只保护自己的寿命，不保护随意捕获的外部指针。

QObject::disconnect(connection)

  • 参数怎样填：传保存的连接句柄。
  • 作用与返回结果：返回 bool，表示是否成功断开。
  • 调用时机与易错点：已经排队的调用需要结合实际情况处理；用请求编号拒绝旧结果更可靠。

setObjectName(name)

  • 参数怎样填：字符串逻辑标识。
  • 作用与返回结果：为测试、样式或 findChild 提供名称；返回 void。
  • 调用时机与易错点：C++ 变量名不会自动成为 objectName，改其中一个不自动改另一个。

children()

  • 参数怎样填：无参数。
  • 作用与返回结果：返回直接 QObject 子对象列表。
  • 调用时机与易错点：不是整个后代树；值类型 QString 不会出现在对象树中。

deleteLater()

  • 参数怎样填：无参数。
  • 作用与返回结果：投递延迟删除，返回 void。
  • 调用时机与易错点：不是立即 delete；依赖相应线程的事件处理与结束机制，调用后不再发起依赖其长期存活的新工作。

QPointer<T>(object)

  • 参数怎样填：观察一个 QObject 派生对象。
  • 作用与返回结果：对象真正销毁后观察指针清空。
  • 调用时机与易错点：不延长寿命，不提供跨线程锁；隐藏窗口不会使它清空。

moveToThread(thread)

  • 参数怎样填：目标 QThread 指针。
  • 作用与返回结果：Qt 6.8 返回 bool，成功后改变线程归属。
  • 调用时机与易错点：有 parent 的对象不能随意移动；普通函数直接调用仍在调用者线程运行。
