前置：第 33、34 章。目标：把界面拆成可复用组件，并保留正确的数据流。

绑定是关系，不是一次复制

text: counter.count 建立依赖，count 通知变化后会重新求值；在点击处理里再写 label.text = "固定"，通常会替换原绑定。后续 count 变化而 label 不更新时，先检查有没有命令式赋值覆盖绑定。

需要重新建立关系时可用 Qt.binding，但更清楚的设计通常是修改数据源，让声明式表达式继续负责显示。C++ getter 应快速、无副作用；NOTIFY 只在值真正改变时发出。

一个可以单独放入文件的组件

新建 StudyCard.qml，将它加入 13_quick 的 qt_add_qml_module 的 QML_FILES 后重新配置：

import QtQuick
import QtQuick.Controls
import QtQuick.Layouts

Frame {
    id: root
    required property string title
    property int minutes: 30
    signal startRequested()
    ColumnLayout {
        anchors.fill: parent
        Label { text: root.title; Layout.fillWidth: true }
        Label { text: "计划 %1 分钟".arg(root.minutes) }
        Button { text: "开始学习"; onClicked: root.startRequested() }
    }
}

父页面使用 StudyCard { title: "信号槽"; onStartRequested: counter.increment() }。子组件发意图，父页面决定业务动作；不要让卡片偷偷依赖外部某个名为 counter 的 id。required property 缺失会产生创建错误，应先看应用输出。

布局与状态

使用 RowLayout/ColumnLayout 时，让 Layout 属性控制其中的直接子项尺寸；不要对同一直接子项同时使用 anchors.fill 和 Layout.fillWidth，形成冲突。anchors.fill 用在布局容器内部的内容和父容器关系时要区分层级。

加载页面至少区分 loading、content、empty、error。没有任务不是网络失败；首次加载也不应显示“没有数据”。先用属性和 visible 实现，再按需要学习 Loader、StackView 和 States，不急于让全部状态都变成动画。

动手检查

复制两张 StudyCard，分别传不同标题，确认互不共享意外状态。再将 C++ count 绑定到一个 Label，故意用按钮直接赋值改 text，观察绑定丢失后恢复。最后给错误状态提供重试按钮。

验收：组件接口写明输入属性和输出信号；缺少 required 参数能定位；更新 C++ 属性后界面自动刷新。本文组件需加入课程 QML 工程构建，不是独立可执行程序。

QML、测试与工程诊断：参数、结果与时机

QQmlApplicationEngine::loadFromModule(uri, typeName)

  • 参数怎样填：课程使用 Course 与 Main。
  • 作用与返回结果：加载模块中的根类型，返回 void。
  • 调用时机与易错点：配置 URI、资源名或 required 属性错误会使创建失败，连接 objectCreationFailed 处理退出。

Q_PROPERTY(... READ ... NOTIFY ...)

  • 参数怎样填：这是元对象声明宏，不是运行时函数。
  • 作用与返回结果：使属性可被读取并通知变化。
  • 调用时机与易错点：NOTIFY 的发送必须由你的代码保证；getter 不应执行长时间磁盘或网络工作。

Counter::increment()

  • 参数怎样填：课程自定义 Q_INVOKABLE，无参数。
  • 作用与返回结果：改变 count 并发 countChanged。
  • 调用时机与易错点：Q_INVOKABLE 只暴露调用能力，不自动启动线程。

QSignalSpy(sender, signal)

  • 参数怎样填：被观察对象和信号指针。
  • 作用与返回结果：创建信号记录器，用 isValid 检查。
  • 调用时机与易错点：尽量在动作前创建，以免错过已经同步发出的信号。

QSignalSpy::wait(timeout)

  • 参数怎样填：最长等待毫秒数。
  • 作用与返回结果：在超时内收到新信号返回 true。
  • 调用时机与易错点：先检查已有数量再 wait，避免信号已发生却继续等待下一次。

QVERIFY(expr) / QCOMPARE(actual, expected)

  • 参数怎样填：测试条件或实际值与期望值。
  • 作用与返回结果：失败记录上下文并结束当前测试函数。
  • 调用时机与易错点：它们是测试宏，不是给真实用户处理错误的界面。

QTRY_VERIFY(expr) / QTRY_COMPARE(actual, expected)

  • 参数怎样填：可在事件循环中逐步成立的条件。
  • 作用与返回结果：重试直到成立或超时。
  • 调用时机与易错点：不是无限等待；比固定 sleep 更能适应不同机器速度。

QTest::mouseClick(widget, button)

  • 参数怎样填：控件与鼠标按钮等参数。
  • 作用与返回结果：模拟交互。
  • 调用时机与易错点：应测真实窗口的用户结果，而不是仅证明 Qt 自带按钮能发信号。

QLoggingCategory(...) / qCWarning(category)

  • 参数怎样填：日志分类和输出表达式。
  • 作用与返回结果：按类别组织诊断。
  • 调用时机与易错点：不会自动写日志文件、轮转或删除敏感信息，仍需明确日志策略。

QProcess 等外部工具

  • 参数怎样填：本课程部署脚本实际调用 windeployqt，而非此处启动 Qt 类。
  • 作用与返回结果：部署命令收集 DLL、插件和 QML。
  • 调用时机与易错点：工具返回成功不证明所有 GPU、驱动、用户输入路径和第三方许可均已验收。

阅读任务：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 完整函数手册 继续查阅。
