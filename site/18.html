当前工作目录不是程序目录

从 IDE、终端和资源管理器启动时，工作目录可能不同。静态资源用 qrc，用户数据用 QStandardPaths，用户选择文件用 QFileDialog。安装目录可能不可写，不能默认把数据库放在 exe 旁边。

QFile::open、readAll、write 都可能失败。读取失败应保留原界面内容，保存失败应保留未保存状态。课程编辑器明确处理 UTF-8 文本，不宣称能无损识别所有历史编码；二进制文件不要通过 QString 中转。

整份文档保存

QSaveFile 先写临时文件，再通过 commit 完成替换，适合保存完整文档。每一步都检查结果，并比较写入字节数。不要调用 close 来代替 commit。它不能替代数据库事务、备份，也不能保证所有存储硬件断电情形下的数据持久性。

QSaveFile file(path);
const QByteArray bytes = text.toUtf8();
if (!file.open(QIODevice::WriteOnly)) return false;
if (file.write(bytes) != bytes.size()) return false;
return file.commit();

大文件不宜一次 readAll；可按块读取，展示进度，且在工作线程处理 CPU 密集解析。不要在处理文件路径时用字符串 replace 粗暴处理斜杠；QDir、QFileInfo 已提供组合和路径检查功能。

练习：给编辑器加“最近打开文件”，不存在时给出提示；在无写权限路径或无效路径测试失败分支。验收：文件对话框取消不报错、不清空文档；UTF-8 中文保存再打开内容一致。 参考：QSaveFile。

配套完整源码

在根工程构建本章目标：04_editor。以下是仓库内同一份文件，修改请到 examples 目录。

main.cpp

#include <QtWidgets>
#include <QSaveFile>
class Editor : public QMainWindow {
public:
    Editor() {
        setCentralWidget(edit_); resize(760,500);
        auto *menu = menuBar()->addMenu(QStringLiteral("文件"));
        auto *open = menu->addAction(QStringLiteral("打开")); open->setShortcut(QKeySequence::Open);
        auto *save = menu->addAction(QStringLiteral("保存")); save->setShortcut(QKeySequence::Save);
        connect(open,&QAction::triggered,this,[this] {
            if(!confirm()) return;
            const QString path=QFileDialog::getOpenFileName(this,QStringLiteral("打开 UTF-8 文本"));
            if(path.isEmpty()) return;
            QFile f(path);
            if(!f.open(QIODevice::ReadOnly)) { error(f.errorString()); return; }
            const QByteArray bytes=f.readAll();
            if(f.error()!=QFileDevice::NoError) { error(f.errorString()); return; }
            edit_->setPlainText(QString::fromUtf8(bytes)); path_=path;
            edit_->document()->setModified(false); setWindowTitle(path_);
        });
        connect(save,&QAction::triggered,this,[this] { saveFile(); });
    }
protected:
    void closeEvent(QCloseEvent *event) override { if(confirm()) event->accept(); else event->ignore(); }
private:
    QTextEdit *edit_=new QTextEdit(this);
    QString path_;
    void error(const QString &message) { QMessageBox::warning(this,QStringLiteral("文件错误"),message); }
    bool saveFile() {
        QString target=path_;
        if(target.isEmpty()) target=QFileDialog::getSaveFileName(this,QStringLiteral("保存 UTF-8 文本"));
        if(target.isEmpty()) return false;
        QSaveFile f(target); const auto bytes=edit_->toPlainText().toUtf8();
        if(!f.open(QIODevice::WriteOnly) || f.write(bytes)!=bytes.size() || !f.commit()) {
            error(f.errorString()); return false;
        }
        path_=target; edit_->document()->setModified(false); setWindowTitle(path_); return true;
    }
    bool confirm() {
        if(!edit_->document()->isModified()) return true;
        const auto choice=QMessageBox::question(this,QStringLiteral("未保存"),QStringLiteral("是否保存修改？"),
            QMessageBox::Save|QMessageBox::Discard|QMessageBox::Cancel,QMessageBox::Save);
        return choice==QMessageBox::Discard || (choice==QMessageBox::Save && saveFile());
    }
};
int main(int argc,char **argv) {
    QApplication app(argc,argv); Editor w; w.show();
    if(app.arguments().contains("--smoke")) QTimer::singleShot(150,&app,&QCoreApplication::quit);
    return app.exec();
}

字符串、配置与文件：参数、结果与时机

QString::trimmed() / isEmpty()

  • 参数怎样填：无参数。
  • 作用与返回结果：前者返回去首尾空白的新字符串；后者返回长度是否为 0。
  • 调用时机与易错点：trimmed 不原地修改；必须接收结果或继续链式调用。

QString::arg(value)

  • 参数怎样填：占位符替换值，可链式调用。
  • 作用与返回结果：返回替换后的新 QString。
  • 调用时机与易错点：不是 SQL 参数绑定；需要控制小数格式时选择对应重载。

QString::toInt(ok, base)

  • 参数怎样填：可传 bool 指针与进制，默认十进制。
  • 作用与返回结果：返回 int；通过 ok 区分真实 0 与解析失败。
  • 调用时机与易错点：不要直接相信失败时的默认数字，也要额外检查业务范围。

QString::toUtf8() / fromUtf8(bytes)

  • 参数怎样填：前者无参数，后者接字节。
  • 作用与返回结果：在 Unicode 文本与 UTF-8 QByteArray 之间转换。
  • 调用时机与易错点：不要将半个多字节字符单独解码后拼接；协议先拆完整帧。

QString::size() / QByteArray::size()

  • 参数怎样填：无参数。
  • 作用与返回结果：分别表示 UTF-16 代码单元数和字节数。
  • 调用时机与易错点：都不自动等于用户看到的字符数；接口限制必须写清单位。

QSettings::value(key, defaultValue)

  • 参数怎样填：键名和键缺失时的默认 QVariant。
  • 作用与返回结果：返回 QVariant，可进一步检查转换结果。
  • 调用时机与易错点：默认值只处理缺失，不自动修复存在但内容损坏的值。

QSettings::setValue(key, value)

  • 参数怎样填：键名与新值。
  • 作用与返回结果：记录配置更新，返回 void。
  • 调用时机与易错点：不是数据库事务或密码加密；多个字段的更新语义需自行设计。

QSettings::sync() / status()

  • 参数怎样填：无参数。
  • 作用与返回结果：sync 同步存储；status 返回错误状态。
  • 调用时机与易错点：应在 sync 后检查状态并反馈保存失败，不能无条件显示成功。

QSettings::fileName()

  • 参数怎样填：无参数。
  • 作用与返回结果：返回实际配置位置。
  • 调用时机与易错点：原生格式可能是注册表相关位置；本例选择显式 INI 便于观察。

QStandardPaths::writableLocation(type)

  • 参数怎样填：如 AppConfigLocation 或 AppDataLocation。
  • 作用与返回结果：返回当前应用对应的可写位置 QString。
  • 调用时机与易错点：查询前设置应用标识，可能为空；返回目录不表示文件已创建。

QDir::mkpath(path)

  • 参数怎样填：路径。
  • 作用与返回结果：返回 bool，递归创建目录或确认已存在。
  • 调用时机与易错点：失败需反馈，不能继续把写入错误解释成空数据。

QFile::open(mode)

  • 参数怎样填：ReadOnly、WriteOnly 等打开模式。
  • 作用与返回结果：返回 bool，成功后才能 read/write。
  • 调用时机与易错点：文件不存在、权限、目录等都会导致失败，读取前检查。

QFile::readAll()

  • 参数怎样填：无参数。
  • 作用与返回结果：返回剩余可读 QByteArray。
  • 调用时机与易错点：空内容与读取失败不同，还需 error()；大文件不要不设上限地一次全读。

QIODevice::write(bytes)

  • 参数怎样填：要写入的 QByteArray。
  • 作用与返回结果：返回实际接受的字节数 qint64，-1 表示失败。
  • 调用时机与易错点：检查数值与目标长度；socket 接受不等于远端业务处理成功。

QSaveFile::commit()

  • 参数怎样填：无参数。
  • 作用与返回结果：完成临时写入并替换目标，返回 bool。
  • 调用时机与易错点：只在写入完全成功后调用；失败不能更新文档路径或清除修改标记。

errorString()

  • 参数怎样填：无参数；具体类如 QFile 或 socket。
  • 作用与返回结果：返回可读错误说明。
  • 调用时机与易错点：要先确认哪个对象和操作失败；旧错误文本不一定代表本次操作状态。

QTemporaryDir::isValid() / filePath(name)

  • 参数怎样填：检查目录或生成其内部文件路径。
  • 作用与返回结果：返回 bool / QString。
  • 调用时机与易错点：临时目录必须活过所有文件操作，离开作用域会自动清理。

QJsonDocument::fromJson(bytes, error)

  • 参数怎样填：UTF-8 JSON 字节与错误输出指针。
  • 作用与返回结果：返回文档对象；error 提供语法错误。
  • 调用时机与易错点：语法合法后仍需 isObject/isArray 和逐字段类型校验。

QJsonDocument::toJson(format)

  • 参数怎样填：默认缩进或 Compact。
  • 作用与返回结果：返回序列化 QByteArray。
  • 调用时机与易错点：不自动验证你的业务规则或承诺旧版本兼容。

QJsonObject::value(key)

  • 参数怎样填：字符串键。
  • 作用与返回结果：返回 QJsonValue，之后检查类型再读取。
  • 调用时机与易错点：缺失、null、空文本含义不同，不能全部默认成合法数据。

QWidget::setStyleSheet(qss)

  • 参数怎样填：样式字符串。
  • 作用与返回结果：更新控件样式。
  • 调用时机与易错点：不是 HTML/CSS 浏览器；样式只能改变展示，不能完成业务状态迁移。

QTextDocument::setModified(false)

  • 参数怎样填：bool 修改标记。
  • 作用与返回结果：标记文档与保存状态一致。
  • 调用时机与易错点：仅在真正读取或保存成功后清除；失败时保留原状态。
