七 · Qt 与 OpenGL、Vulkan 图形集成 · 推荐路线 50 / 67

49 · 图形预备课：CPU、GPU、坐标与一帧的形成

学完这一章应能解释什么

为什么 Qt 按钮点一下就能变化，而画一个三角形还要准备顶点、着色器和渲染目标？CPU 负责事件、业务与发出命令；GPU 按管线处理大量顶点和像素。图形 API 是二者协作的接口，Qt 则承担窗口、事件、输入和一部分平台资源管理。使用 Qt 不意味着可以忽略 GPU 资源寿命。

本扩展先做 Widgets 中的 OpenGL 三角形，再做 QVulkanWindow 的 Vulkan 清屏。后续章节把矩阵、纹理、管线和同步作为逐步扩展。当前 Vulkan 示例没有偷偷包含三角形管线；读到进阶设计时，应按章节步骤添加并验证。

第一步：把数据和图像区分开

一个顶点不只是位置，还可以包含颜色、法线和纹理坐标。本课程第一份顶点记录为五个 float：x、y、r、g、b。三条记录共 15 个 float，若 float 为 4 字节，则上传大小 60 字节，每条记录跨度 20 字节。

CPU 数组是一段普通内存；VBO 是 GPU 可读的缓冲存储。上传之后修改 CPU 数组，不会自动改变已上传的数据，需要明确再次写入。反过来，提交绘制命令也不代表 CPU 此刻拿到了最终图像，读回通常有同步成本。

第二步：顺着渲染管线走

阶段 输入 输出 你需要决定的事
顶点读取 缓冲与布局描述 每个顶点的属性 类型、偏移、跨度
顶点着色器 位置、颜色、uniform 裁剪空间位置与插值数据 坐标变换
图元装配 顶点序列与拓扑 三角形等图元 三个点如何组成一个面
光栅化 图元与视口 片元及插值属性 哪些屏幕样本被覆盖
片元着色器 插值颜色、纹理等 候选颜色 每个片元怎么着色
深度、模板、混合 候选结果与已有缓冲 更新后的附件内容 遮挡与透明关系
呈现 可显示图像 用户看到的一帧 窗口系统与交换链

片元不完全等于最终屏幕像素：多重采样、深度失败和混合都可能改变最后结果。顶点着色器不能直接当作“按顺序画一个屏幕点”的函数来理解。

第三步：走一遍坐标计算

常见顺序是 clip = projection * view * model * position。列向量约定下，右边的 model 先作用；改变乘法顺序会改变结果。model 把物体坐标送进世界，view 表达观察者的位置与朝向，projection 决定投影。

输出裁剪坐标之后还要按 w 做透视除法。若结果为 (0.5, 0, 0, 1)，则 x 的标准化值为 0.5；若为 (0.5, 0, 0, 2)，除法后 x 为 0.25。这解释了为什么透视投影不是简单把 z 丢掉。

Qt 控件尺寸通常是逻辑单位；渲染目标往往使用物理像素。逻辑宽 640、设备像素比 1.5 的图像可能宽 960。涉及 framebuffer、readback 和鼠标拾取时，先确定坐标所在空间，避免直接把两者混用。

第四步：认清两套 API 的责任差异

OpenGL 使用上下文与大量当前状态；绑定某个缓冲或 program 后，后续命令受其影响。Vulkan 把更多状态、内存与同步显式化，不能靠“上一条调用应该已经完成”推断安全性。显式不自动意味着更快，错误同步同样会让 GPU 长时间空闲。

本教程只走现代 OpenGL 3.3 Core 路线，不使用 glBegin/glEnd 的旧固定管线。Vulkan 从 1.0 可用功能和 Qt 6.8 QVulkanWindow 开始，不把新版本动态渲染教程的代码无条件混进默认 render pass 示例。

实验与验收

  1. 手算三个顶点的字节位置：第一个颜色偏移 8 字节，第二个位置偏移 20 字节。
  2. 画 CPU 数组、GPU buffer、command、framebuffer、显示窗口五个盒子，标出谁拥有谁。
  3. 写出窗口缩放时可能变化的资源，再对照第 55 章的 Vulkan 生命周期。

验收：能区分数据上传、命令提交、GPU 完成、屏幕显示四个时刻；能解释 stride、offset、逻辑尺寸和物理像素。遇到黑屏先检查每个阶段的输入输出，不同时改十个状态。
