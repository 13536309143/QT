03 · 安装与环境：项目内的 Qt 6

目录和工具的职责

本仓库的 sdk/6.8.3/msvc2022_64 用于存放 Qt SDK；.tools 用于本地安装工具；build 用于编译结果。这三个目录均不提交到 Git。项目脚本根据仓库位置定位 SDK 和构建目录。

需要 Visual Studio 2022 或 Build Tools，并选择“使用 C++ 的桌面开发”、MSVC v143 和 Windows SDK。只安装 C# 工作负载不能编译本课程。还需要 CMake 3.21+、Python 3.10+（仅安装脚本需要）。Qt Creator 可选；Visual Studio、VS Code 和命令行同样可用。

具体操作

  1. 在项目根目录打开 PowerShell，执行 powershell -ExecutionPolicy Bypass -File scripts/bootstrap-qt.ps1。脚本用独立虚拟环境安装固定版本 aqtinstall，再从 Qt 分发源获取课程所需 SDK。
  2. 双击 build.cmd，或在终端执行 scripts\build.cmd。它会寻找 VS 2022，调用开发环境脚本，再执行 CMake 配置、编译和测试。
  3. 执行 scripts\run.cmd 01_hello。运行脚本临时配置 Qt 的 DLL、平台插件和 QML 路径，不修改系统 PATH。
  4. 如果使用 Qt Creator，打开根目录 CMakeLists.txt。添加 Qt 版本时选择 SDK 下的 bin/qmake.exe，Kit 选择对应 MSVC x64 编译器与 CMake。把构建目录改为独立目录 build-creator，不要混用命令行的缓存。

手动构建

在 x64 Native Tools Command Prompt for VS 2022 中执行：

cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="$PWD/sdk/6.8.3/msvc2022_64"
cmake --build build --config Release --parallel 2
ctest --test-dir build -C Release --output-on-failure

多配置生成器用 --config Release 选择配置，单写 CMAKE_BUILD_TYPE 并不能替代它。Qt SDK 的编译器体系必须和项目一致；MSVC Qt 库不能直接给 MinGW 链接。同时安装多个 Qt 版本时，应查看 CMake 的 Qt6_DIR，确认当前 Kit 使用预期的 SDK。

验收：SDK 的 qmake -query QT_VERSION 返回 6.8.3，构建日志使用 Qt6，所有测试通过。
