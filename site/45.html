45 · 工程习惯、GitHub 准备和协作

什么应该进仓库

提交教程 Markdown、离线网页、C++/QML/ui/qrc 源码、CMake、脚本、测试和工作流。忽略 sdk、.tools、build、dist、IDE 用户配置、日志和实际数据库。CMakeUserPresets 用于个人机器，不提交私有绝对路径。

README 必须让第一次访问的人知道这是什么、适合谁、版本要求、安装命令、如何构建和运行、从哪章开始、许可是什么。把演示限制诚实写出来，不添加尚未运行的 CI 通过徽章，不编造仓库地址或作者身份。

本地检查到公开发布

发布时先新建空仓库，再检查 git status、git diff --cached --stat，确认暂存内容完整且不含 SDK 与私人数据，最后设置远程地址并 push。发布操作示例放在 PUBLISHING.md，命令中的占位符必须替换。

CI 在 Windows runner 上安装固定 Qt，构建全部示例并执行测试。工作流成功需要实际 GitHub 运行才能确认；本地通过不能冒充远程已通过。离线教程可直接阅读；若以后使用 GitHub Pages，需要选择部署站点内容，不必把 SDK 暴露到网页目录。

练习：让一位没有接触项目的人只读 README，尝试构建首个例子，把他遇到的问题加入文档。验收：仓库源码体积合理，所有相对链接有效，命令可在仓库根目录直接执行。
