一、先把三个“编号”分清

currentFrame 是 Qt 的并发帧资源槽，范围与 concurrentFrameCount 相关；currentSwapChainImageIndex 是当前交换链图像编号；业务 requestId 是应用自己定义的请求序号。三者不保证相等，也不保证始终按同一速度递增。

为 uniform 等“CPU 每帧写、GPU 会读”的数据分配资源时，按 Qt 当前并发帧槽组织。若交换链有三张图但并发帧槽有两份，你不能直接用交换链图像编号访问两元素数组。

二、一个具体的数据竞争

CPU 为帧 A 写入角度 10 并提交，GPU 还没读完；CPU 又把同一内存改成角度 20 供帧 B 使用。结果可能撕裂或读到不属于该帧的数据。解决思路是帧槽隔离及正确复用时机，不是随手在两个 write 之间 sleep(1)。

使用 QVulkanWindow 管理的帧资源路径时，遵循它提供的当前槽和回调约束。额外自行提交的 transfer queue、compute queue 或异步读回，不会仅因调用 frameReady 就全部自动同步，必须明确自己的完成条件。

三、fence、semaphore、barrier 的区别

工具 主要协调对象 常见用途 不能替代什么
fence CPU 观察 GPU 工作完成 等待提交完成后复用 CPU 资源 不能当作 shader 内任意内存屏障
semaphore GPU 提交之间的依赖 获取图像、队列提交、呈现依赖 不自动描述所有资源访问类型
pipeline barrier 设备执行与内存访问依赖 transfer 写到 shader 读等 不是 CPU 完成通知

执行顺序和内存可见性是相关但不同的问题。源/目标 stage 表达哪些执行阶段需要建立依赖，access mask 表达相应读写访问。不要使用“全部阶段等全部阶段”作为永久方案，也不要因同一队列顺序提交就认为所有内存危险都消失。

Qt 已管理的获取、提交和呈现同步，不在本例手动再添加另一套相互冲突的 fence/semaphore。只有明确离开其管理边界的工作，才设计并验证额外同步。

四、descriptor 不是数据本体

shader 中的 uniform buffer、采样图像等通过 descriptor 暴露。descriptor set layout 描述 binding 编号、类型、数量和 stage 可见性；descriptor pool 管理分配容量；descriptor set 记录实际资源引用；pipeline layout 决定着色器可使用的布局。

例如 set=0、binding=0 的 uniform buffer：shader 声明、layout 的 binding、vkUpdateDescriptorSets 的 dstBinding 必须对应。bufferInfo 还要指定 buffer、offset、range，范围不应越界；动态 offset 要满足设备对齐约束。

descriptor 引用了 buffer，不代表替你拥有或延长了 buffer 的 GPU 使用寿命。正在被 GPU 使用的 set 也不能在未满足相应规则时随意重写。先做每帧一组资源的简单方案，再根据测量考虑更复杂的更新策略。

五、纹理上传为什么要转换布局

VkImage 的 layout 表达图像当前用途和访问约束，不是图片文件格式。常见过程是建立 image 和 memory，用 staging buffer 准备像素，将图像转换到 transfer 目标布局，copy，再转换到 shader 读取布局，同时建立合适的阶段与访问依赖。

image view 解释图像的格式、层级与子资源；sampler 定义过滤和寻址；二者与图像对象本身不同。descriptor 中声明的 imageLayout 应与实际使用时的布局匹配，不能只改 descriptor 字段就认为真的发生了 layout transition。

Qt 默认交换链图像和 render pass 的布局处理属于其窗口路径；不要给默认附件随意插入与 pass 约定冲突的转换。先在自己拥有的离屏 image 上学习，再研究与交换链结合。

六、交换链重建与设备丢失

resize、窗口暴露变化和 surface 条件可能导致交换链重建。释放自建的 framebuffer、尺寸相关 image/view 以及必要的 pipeline，再依据新 imageSize、format 与 sampleCount 建立新资源。只改一个 width 成员不等于整套依赖都已更新。

device lost 不是普通的“下一帧重画即可”。应停止继续录制旧资源、记录诊断并进入应用设计的恢复或退出流程。资源清理还要考虑部分初始化成功的状态。

实验：在纸上给两帧槽分别列 uniform buffer 与 descriptor；模拟 CPU 比 GPU 快两帧；指出哪个时刻可以重写。实现前先画资源状态图，再开同步验证。没有实际验证层检查时，应明确记录尚未验证的同步实验。
