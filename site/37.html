前置：第 36 章。目标：让测试对应用户风险，并可靠等待异步结果。

分层选择测试对象

层次 应验证的行为 不足以证明的事
规则与协议 空值、长度、拆帧、非法输入 窗口按钮布局正确
持久化 CRUD、事务、重开文件 真机磁盘永久不会失败
交互 点击、输入、取消、焦点 所有显卡与缩放都一致
启动 插件和资源可加载 全部业务分支正确

先挑可能误删、丢数据、错对象的路径，再覆盖正常演示。测试调用实际业务接口，不复制一份相同逻辑在测试内比较。每个测试独立创建临时数据，不依赖执行顺序。

一个最小交互测试

以下代码放在 Qt Test 测试类的槽函数里，已包含 QtWidgets 与 QtTest：

void clickClearsInput() {
    QWidget window;
    QLineEdit input(&window);
    QPushButton clear(QStringLiteral("清空"), &window);
    QObject::connect(&clear, &QPushButton::clicked, &input, &QLineEdit::clear);
    input.setText(QStringLiteral("待清空"));
    QTest::mouseClick(&clear, Qt::LeftButton);
    QCOMPARE(input.text(), QString());
}

这只示范测试工具，不能代替对真实窗口类的测试。实践时应实例化自己的 Form，按 objectName 找到控件，验证按钮造成的业务结果。不要断言每一个布局坐标来锁死可变的界面实现。

等待条件，不是猜时间

用 QTRY_VERIFY/QTRY_COMPARE 让事件循环推进直到条件成立或超时。QSignalSpy 先检查 isValid；信号可能已在 spy.wait 前发出，因此先检查数量，再决定是否等待。固定 sleep 在快机器浪费时间，在慢机器仍可能不够。

网络测试用回环服务和随机可用端口，不访问公共网站；为消息拆成两段、两行合并、超长、断线、超时分别设计场景。16_tcp/lineprotocol.h 的独立解析器允许不连网络就验证分帧规则。

故意让测试失败一次

修改解析器长度比较符，确认边界测试失败，再恢复；若测试仍通过，说明案例没有击中规则。数据库迁移练习注入一次执行失败，确认回滚，不在真实任务库上试验。

验收：重复运行结果一致，失败信息指出输入与预期；未测试的手工流程单独记录。现有自动测试的覆盖范围以 tests 源码和实际运行报告为准，不把本章所有建议写成已经实现的测试。

参考：QTest、QSignalSpy。

QML、测试与工程诊断：参数、结果与时机

QQmlApplicationEngine::loadFromModule(uri, typeName)

  • 参数怎样填：课程使用 Course 与 Main。
  • 作用与返回结果：加载模块中的根类型，返回 void。
  • 调用时机与易错点：配置 URI、资源名或 required 属性错误会使创建失败，连接 objectCreationFailed 处理退出。

Q_PROPERTY(... READ ... NOTIFY ...)

  • 参数怎样填：这是元对象声明宏，不是运行时函数。
  • 作用与返回结果：使属性可被读取并通知变化。
  • 调用时机与易错点：NOTIFY 的发送必须由你的代码保证；getter 不应执行长时间磁盘或网络工作。

Counter::increment()

  • 参数怎样填：课程自定义 Q_INVOKABLE，无参数。
  • 作用与返回结果：改变 count 并发 countChanged。
  • 调用时机与易错点：Q_INVOKABLE 只暴露调用能力，不自动启动线程。

QSignalSpy(sender, signal)

  • 参数怎样填：被观察对象和信号指针。
  • 作用与返回结果：创建信号记录器，用 isValid 检查。
  • 调用时机与易错点：尽量在动作前创建，以免错过已经同步发出的信号。

QSignalSpy::wait(timeout)

  • 参数怎样填：最长等待毫秒数。
  • 作用与返回结果：在超时内收到新信号返回 true。
  • 调用时机与易错点：先检查已有数量再 wait，避免信号已发生却继续等待下一次。

QVERIFY(expr) / QCOMPARE(actual, expected)

  • 参数怎样填：测试条件或实际值与期望值。
  • 作用与返回结果：失败记录上下文并结束当前测试函数。
  • 调用时机与易错点：它们是测试宏，不是给真实用户处理错误的界面。

QTRY_VERIFY(expr) / QTRY_COMPARE(actual, expected)

  • 参数怎样填：可在事件循环中逐步成立的条件。
  • 作用与返回结果：重试直到成立或超时。
  • 调用时机与易错点：不是无限等待；比固定 sleep 更能适应不同机器速度。

QTest::mouseClick(widget, button)

  • 参数怎样填：控件与鼠标按钮等参数。
  • 作用与返回结果：模拟交互。
  • 调用时机与易错点：应测真实窗口的用户结果，而不是仅证明 Qt 自带按钮能发信号。

QLoggingCategory(...) / qCWarning(category)

  • 参数怎样填：日志分类和输出表达式。
  • 作用与返回结果：按类别组织诊断。
  • 调用时机与易错点：不会自动写日志文件、轮转或删除敏感信息，仍需明确日志策略。

QProcess 等外部工具

  • 参数怎样填：本课程部署脚本实际调用 windeployqt，而非此处启动 Qt 类。
  • 作用与返回结果：部署命令收集 DLL、插件和 QML。
  • 调用时机与易错点：工具返回成功不证明所有 GPU、驱动、用户输入路径和第三方许可均已验收。

阅读任务：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 完整函数手册 继续查阅。
