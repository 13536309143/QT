32 · SQLite 进阶：事务、迁移与分页

前置：第 31 章；综合项目的数据结构见第 42 章。目标：让数据库扩展后仍能打开旧文件，并避免半次导入。

事务维护一组操作的整体结果

假设要导入 100 条任务，第 40 条无效。如果需求是“全成功才算成功”，就必须让失败时前 39 条也不留下。先验证格式，再开事务；每次执行检查错误，任何失败 rollback；最后检查 commit 是否成功。不要把关闭进度窗口等同于事务完成。

以下片段假定 db 是当前线程已打开的 QSQLITE 连接，rows 已经过标题规则校验：

bool importRows(QSqlDatabase db, const QStringList &rows) {
    if (!db.transaction()) return false;
    QSqlQuery query(db);  // 开事务后创建查询
    if (!query.prepare("INSERT INTO tasks(title) VALUES(?)")) {
        db.rollback(); return false;
    }
    for (const auto &title : rows) {
        query.bindValue(0, title);
        if (!query.exec()) { db.rollback(); return false; }
    }
    query.finish();
    if (db.commit()) return true;
    db.rollback();
    return false;
}

真实接口还需返回具体错误；false 只是此处演示控制流。SQL 占位符绑定数据值，不能直接绑定表名或 ORDER BY 的列名；动态列只能从明确白名单选择。

从 v1 到 v2 的迁移

  1. 在数据库副本上读取 PRAGMA user_version；先明确旧库没有版本号时视为什么版本。
  2. 开事务，执行 ALTER TABLE tasks ADD COLUMN priority INTEGER NOT NULL DEFAULT 0。
  3. 为旧数据检查或填充默认值，更新 PRAGMA user_version = 2，提交。
  4. 未知更高版本停止自动写入，提示升级应用；不要为了能打开而删除表重建。

先备份、再演练迁移失败回滚。TaskDesk 当前版本没有实现这条迁移，本章是扩展步骤，不能声称现有程序已支持 priority 字段。DDL/事务能力与数据库有关，本课程只在 SQLite 范围讨论。

分页和索引

少量数据用 LIMIT/OFFSET 易理解；大量翻页时基于稳定排序键继续读取，例如 WHERE id > ? ORDER BY id LIMIT ?。同时按其他字段排序时需要组合游标和确定的并列顺序。索引应围绕真实 WHERE/ORDER BY 设计，用 EXPLAIN QUERY PLAN 检查，不盲目为每列建索引。

每个线程创建、使用并移除自己的数据库连接。QSqlDatabase 的拷贝是连接句柄，不是独立物理连接；随手复制给 worker 并不能跨线程安全查询。

验收：批次中间失败不留半批记录；旧数据库升级后数据保留；未知版本不会被覆盖。练习答案要点：版本更新与结构修改放同一事务，查询和模型销毁后再 removeDatabase。

参考：QSqlDatabase、QSqlQuery。
