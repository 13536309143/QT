28 · 综合项目 TaskDesk：需求、架构和数据流

我们要交付什么

一个本地任务管理器：添加 1~200 单元标题、回车提交、搜索、排序、切换完成、确认删除、重启保留数据、记住窗口位置。界面是中文，数据库保存在系统用户数据目录。第一次启动自动建表，不要求用户安装数据库服务。

三层职责

Window 负责控件与交互；TaskStore 负责验证和 SQL；SQLite 负责持久化。QSqlQueryModel 读取结果供视图展示，代理负责搜索和排序。课程规模暂未引入复杂服务接口；以后加入同步、分页时，再把查询也封装为独立仓储方法。

数据流：输入文本 → store.add → 绑定 INSERT → 成功后 reload → model 查询 → proxy → table。删除流程多了 mapToSource 和稳定 id，防止排序后误删。失败时弹出错误，不清空输入；成功后清空并刷新。

如何读源码

先看 TaskStore::open 的建表，再看 add 的规则，然后读 main 中的应用名称与 AppDataLocation。最后读 Window 构造函数中每个 connect，把每条用户操作画成箭头。局部变量析构与声明逆序：Window 先销毁，Store 后销毁，保证模型不晚于数据库连接。

数据路径可以在调试器中观察 dir；Windows 下由 QStandardPaths 按用户目录决定，不硬编码具体用户名。--smoke 使用测试模式与内存库，避免启动检查污染真实任务。

练习：先添加三个任务，重启，搜索第二个并完成它，再排序并删除。验收：重启后完成状态还在；删除确认选 No 时不变；空输入失败且没有新增空行。
