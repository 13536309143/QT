19 · JSON、配置与数据格式演进

JSON 与设置分工

QJsonDocument 负责 JSON 字节解析，QJsonObject 表示键值对象，QJsonArray 表示数组。解析后先检查 error，再检查顶层类型，再验证每个字段。toInt() 的默认值会掩盖字段不存在或类型错误，业务要求严格时应显式 isDouble/isString 判断。

示例把任务对象写入临时目录，重新读取并打印标题。它退出后自动清理，适合实验；真正数据应使用 AppDataLocation。字段包括 title、done、version，其中 version 为后续迁移预留入口。

数据演进实例

第一版只有 title，第二版加 priority。读取旧版本时，为缺少 priority 的记录补默认值；读到未知更高版本时明确拒绝或进入只读模式，而不是静默删掉不认识的字段。导入外部 JSON 时限制大小、记录数和字符串长度，避免一次解析占满内存。

QSettings 适合窗口位置、主题、最近目录这类偏好设置，不适合大量任务数据，也不是密码保险箱。调用前设置 organizationName 和 applicationName，让存储位置稳定。Windows 的默认 QSettings 后端可能是注册表，不能以为一定会生成 ini 文件。

QSettings settings;
restoreGeometry(settings.value("geometry").toByteArray());
settings.setValue("geometry", saveGeometry());

练习：为示例添加一个 tasks 数组并验证每项 title 非空；故意删去 JSON 的逗号，检查错误偏移。验收：非法 JSON 有错误提示，未知字段不会引发崩溃；能解释配置与业务数据库为何分开。

配套完整源码

在根工程构建本章目标：05_json。以下是仓库内同一份文件，修改请到 examples 目录。

main.cpp

#include <QtCore>
int main(int argc,char **argv) {
    QCoreApplication app(argc,argv);
    QTemporaryDir dir; // 本例退出自动清理，不污染用户目录
    if(!dir.isValid()) return 1;
    QJsonObject object{{"title",QStringLiteral("学习 Qt")},{"done",false},{"version",1}};
    const auto bytes=QJsonDocument(object).toJson();
    QSaveFile out(dir.filePath("task.json"));
    if(!out.open(QIODevice::WriteOnly) || out.write(bytes)!=bytes.size() || !out.commit()) {
        qCritical()<<out.errorString(); return 1;
    }
    QFile in(dir.filePath("task.json"));
    if(!in.open(QIODevice::ReadOnly)) return 2;
    QJsonParseError error;
    auto doc=QJsonDocument::fromJson(in.readAll(),&error);
    if(error.error!=QJsonParseError::NoError || !doc.isObject()) return 3;
    qInfo().noquote()<<doc.object().value("title").toString(); return 0;
}
