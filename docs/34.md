# 34 · C++ 与 QML：属性、通知和类型注册

## 属性是明确的数据契约
Counter 用 Q_PROPERTY 声明 count，READ 指定读取函数，NOTIFY 指定变化通知。Q_INVOKABLE 使 increment 可从 QML 调用；QML_ELEMENT 配合 qt_add_qml_module 生成类型注册信息。C++ 类名 Counter 成为 QML 可创建类型。

不需要每次读属性都从磁盘取值，读取函数应该快速且无意外副作用。setter 应先比较新旧值，相同就返回，不发重复通知；这有助于避免不必要的绑定计算和反馈循环。
```cpp
void setCount(int value) {
    if (count_ == value) return;
    count_ = value;
    emit countChanged();
}
```
当前示例故意将 count 设为只读，外部通过 increment 请求改变，这体现“可观察状态”和“允许的操作”分开。若业务要求直接编辑，再添加 WRITE setter，而不是把所有成员都公开。

## 跨边界的类型和所有权
Qt 支持许多常见值类型转换，但 C++ 自定义类型并不自动变成 QML 认识的类型。列表数据优先提供模型，而不是每次复制庞大 QVariantList。返回 QObject 指针时还要理解引擎所有权，不要假定 QML 和 C++ 都不会销毁它。

UI 绑定调用的 getter 和方法仍在相应线程执行，Q_INVOKABLE 并不自动成为后台任务。耗时操作应启动服务，结果以属性与信号回到 GUI。练习：添加 busy、errorString 两个只读属性，模拟一个异步任务。验收：按钮随 busy 禁用，失败展示 errorString，业务状态在 C++ 只有一份。
参考：[向 QML 暴露 C++ 属性](https://doc.qt.io/qt-6.8/qtqml-cppintegration-exposecppattributes.html)。
