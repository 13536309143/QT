# 43 · 项目拆分：让窗口不再承担全部业务

**前置**：第 42 章。**目标**：为 TaskDesk 的扩展建立清楚边界，避免一开始就堆设计模式。

## 从一次“新增任务”追踪职责

Window 读取输入并显示结果；应用服务组织“新增、刷新、错误反馈”的流程；仓储执行持久化；规则函数检查标题。小项目允许合并一些层，但应能说清每段代码负责什么。

TaskDesk 当前由 Window 与 TaskStore 配合，SQL 查询模型仍参与窗口。不要把教程中的目标架构说成现有代码已经全部实现；可以逐次抽离查询、导入、迁移服务，每次保持行为不变。

## 先提取纯规则

把标题校验整理为不依赖 QWidget 的函数，输入 QString，返回明确结果。例如区分空标题与超长标题，使界面能选择不同提示。规范化和校验顺序固定：trimmed → 空值 → 长度 → 保存。

UI 验证用于及时提醒，仓储边界验证防止其他调用路径绕过。为了避免维护两份规则，让 UI 调用共享规则，而不是分别写两个不同上限。

## 再提取流程，不急着做全局单例

服务通过构造函数获得仓储依赖，窗口通过服务发命令。这样测试可以替换数据源，业务类也不必自己弹 QMessageBox。错误作为返回值或信号向上交付，展示位置由界面决定。

对象之间先列清所有者和观察者。QObject 类可用父子关系；普通值类型优先按值保存；非 QObject 资源适合 RAII。不要为统一形式让所有类都继承 QObject，也不要把每个对象都放进 shared_ptr。

## 一次重构的具体步骤

1. 记录原有新增、空值失败、排序后删除三个流程。
2. 新建验证函数文件，加入 CMake 目标和测试。
3. 让 TaskStore 调用它；保持返回行为，运行原测试。
4. 让界面也调用它提供提前反馈，再运行手工流程。
5. 删除重复规则，检查 include 方向：规则层不包含窗口头文件。

只有出现多个仓储实现或测试替身需求时再加抽象接口。接口不是越多越好，能减少变动传播才有价值。后续可将库目标导出给测试，避免测试依赖整套窗口启动。

验收：标题上限只需改一个规则入口；业务层不弹窗；异常或失败信息能到达用户；重构前后的数据文件仍可打开。参考答案要点：先保持行为，再扩展功能，一次提交做一件可验证的事情。

## 数据库与 TaskDesk：参数、结果与时机

### `QSqlDatabase::addDatabase(driver, name)`

- **参数怎样填**：如 QSQLITE 和唯一连接名。
- **作用与返回结果**：返回连接句柄。
- **调用时机与易错点**：同名会影响旧连接；一个句柄拷贝不是新建独立连接。

### `setDatabaseName(path) / open()`

- **参数怎样填**：路径或 :memory:；打开无参数。
- **作用与返回结果**：设置目标 / open 返回 bool。
- **调用时机与易错点**：失败检查 lastError；SQLite 内存库退出即丢，不能当持久化。

### `QSqlQuery::prepare(sql)`

- **参数怎样填**：含 ? 或命名占位符的 SQL。
- **作用与返回结果**：返回 bool。
- **调用时机与易错点**：准备也会失败；表名和排序字段不能作为普通值占位符绑定。

### `addBindValue(value) / bindValue(index, value)`

- **参数怎样填**：顺序追加值或按位置更新值。
- **作用与返回结果**：把值交给驱动，返回 void。
- **调用时机与易错点**：与 SQL 中占位符顺序对应，不通过 arg 拼接用户标题。

### `QSqlQuery::exec()`

- **参数怎样填**：执行已准备语句，或传 SQL 的重载。
- **作用与返回结果**：返回 bool。
- **调用时机与易错点**：成功不代表一定匹配到某一行；更新/删除还检查受影响行数。

### `QSqlQuery::next() / value(column)`

- **参数怎样填**：推进到下一条结果 / 当前行列号。
- **作用与返回结果**：返回 bool / QVariant。
- **调用时机与易错点**：必须先 next 成功再读 value；不要把查询失败当作合法空结果。

### `numRowsAffected()`

- **参数怎样填**：无参数。
- **作用与返回结果**：返回写操作影响行数，驱动无法提供时可有特殊值。
- **调用时机与易错点**：课程的单主键更新要求 1 行，0 行表示目标可能已经不存在。

### `transaction() / commit() / rollback()`

- **参数怎样填**：数据库连接成员，无参数。
- **作用与返回结果**：均返回 bool。
- **调用时机与易错点**：每个结果都检查；业务整批成功才提交，失败回滚，不弹成功提示。

### `QSqlQuery::finish()`

- **参数怎样填**：无参数。
- **作用与返回结果**：结束活动结果集，保留查询对象。
- **调用时机与易错点**：有些数据库提交前需结束查询；销毁连接前还需让模型和查询退出作用域。

### `QSqlDatabase::removeDatabase(name)`

- **参数怎样填**：连接名。
- **作用与返回结果**：移除命名连接。
- **调用时机与易错点**：不能仍有活动 query/model/外部句柄引用该连接；先销毁使用者。

### `TaskStore::open(path)`

- **参数怎样填**：课程仓储自定义接口。
- **作用与返回结果**：返回 bool；打开并建表。
- **调用时机与易错点**：不是 Qt 自带函数；失败用 store.error 读课程保存的错误。

### `TaskStore::add(title)`

- **参数怎样填**：候选标题。
- **作用与返回结果**：trim 后校验 1~200 UTF-16 单元，成功写入返回 true。
- **调用时机与易错点**：UI 通过验证不代表其他调用者不会绕过，仓储仍要保护规则。

### `TaskStore::complete(id, done) / remove(id)`

- **参数怎样填**：稳定主键与目标完成状态，或删除主键。
- **作用与返回结果**：返回 bool，要求真正影响一行。
- **调用时机与易错点**：id 不是排序后的可见行号；操作后刷新展示并处理失败。

**阅读任务**：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 [完整函数手册](API.md#sql) 继续查阅。
