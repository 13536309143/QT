# 06 · CMake：从源码到程序

## 构建经历哪几步
配置阶段读取 CMakeLists、寻找 Qt 和编译器；生成阶段写出 VS 工程或 Ninja 文件；编译阶段把每个 cpp 变成目标文件；链接阶段把目标文件和 Qt 库组合成可执行程序。找不到头文件通常在编译阶段失败，unresolved external symbol 通常在链接阶段失败。
```cmake
cmake_minimum_required(VERSION 3.21)
project(Hello LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_AUTOMOC ON)
find_package(Qt6 6.8 REQUIRED COMPONENTS Widgets)
add_executable(hello main.cpp)
target_link_libraries(hello PRIVATE Qt6::Widgets)
```
`Qt6::Widgets` 是导入目标，会携带所需头文件路径、库和传递依赖。不要手工拼接 Qt 的 include/lib 路径。`PRIVATE` 表示该链接需求服务于当前目标；库项目公开头文件依赖 Qt 时再考虑 PUBLIC。

## moc、uic、rcc
AUTOMOC 处理 Q_OBJECT 等元对象声明；AUTOUIC 将 ui 文件生成为 C++ 头；AUTORCC 将 qrc 资源打进程序。如果在 main.cpp 内定义 Q_OBJECT 类，示例末尾的 `#include "main.moc"` 是有意保留的。生成目录里的 ui_form.h 和 moc 文件不应手工修改或提交。

## 常用命令
```powershell
cmake --build build --config Release --target 02_counter
ctest --test-dir build -C Release --output-on-failure
cmake --build build --config Debug --target taskdesk
```
切换 Qt 主版本、架构或生成器时用新的构建目录，例如 build-msvc，不要在旧缓存上反复猜。通过 `cmake -LA -N build` 查看缓存。根工程需要 Core、Gui、Widgets、Network、Sql、Test、Quick、QuickControls2；以后开发独立小项目时只链接真正需要的模块。

练习：新增一个只链接 Core 的控制台目标打印当前时间。验收：能单独编译目标，不用重编译全部课程。
参考：[Qt CMake 入门](https://doc.qt.io/qt-6.8/cmake-get-started.html)。
