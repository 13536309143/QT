# 26 · 调试与故障排查：从第一条错误开始

## 把问题定位到阶段
| 现象 | 优先检查 |
|---|---|
| 找不到 Qt6Config.cmake | CMAKE_PREFIX_PATH 指向 SDK 根目录，不是 bin |
| 找不到 cl 或 SDK | VS C++ 工作负载和 x64 开发环境 |
| vtable / metaObject 链接错误 | Q_OBJECT、AUTOMOC、源文件列表、main.moc |
| 缺 Qt6Widgets.dll | 运行路径或 windeployqt 部署 |
| windows 平台插件加载失败 | platforms/qwindows.dll 与同版本依赖 |
| QSQLITE driver not loaded | sqldrivers 插件和 Qt 主版本 |
| QML module not installed | 模块安装、QML 路径、SDK 版本 |
| 点击两次执行两遍 | 是否重复 connect |
| 关闭时崩溃 | 对象寿命、线程退出、悬空 lambda 捕获 |

## 有效调试过程
先用 Debug 构建，在槽函数入口打断点，查看调用栈和局部变量。段错误发生的行可能只是使用了早先已经释放的对象；回溯所有者和销毁时机比随手加 nullptr 更有效。未初始化指针不等于空指针。

qDebug 用于开发日志，qWarning 表示可恢复异常，qCritical 表示关键失败。用 QLoggingCategory 按功能筛选日志；不要把用户密码、访问令牌和完整私人数据写进日志。查插件时可临时设置 QT_DEBUG_PLUGINS=1，定位完成后关闭，避免日常日志被淹没。

## 缩小复现
记录版本、操作顺序、预期、实际和第一条错误，减少到只含必要控件的项目。不要从不同 Qt 版本复制 DLL 到系统目录“试试看”。切换 Kit 后创建新构建目录。练习：移走测试副本中的一个插件，观察诊断并恢复；不要破坏 SDK 原目录。
验收：能将一个错误明确归类为配置、编译、链接、启动或业务逻辑问题。
