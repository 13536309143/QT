# 05 · C++ 补课二：类、继承、lambda 和工程拆分

## 界面类就是普通 C++ 类
成员变量保存状态，成员函数规定行为。把内部状态设为 private，防止外部任意修改。窗口类继承 QWidget 后，可以重写 `paintEvent`、`closeEvent` 等虚函数；`override` 能让编译器检查你是否真的覆盖了基类函数。
```cpp
class Counter final : public QWidget {
public:
    explicit Counter(QWidget *parent = nullptr);
private:
    int count_ = 0;
};
```
头文件声明接口，cpp 实现行为。头文件用 `#pragma once` 或 include guard 避免重复定义。项目中添加 cpp 后，也必须把它加入 CMake target；把文件复制进文件夹不会自动让它参与构建。Qt 的 QObject 通常不允许拷贝，因此窗口对象不要放进要求复制元素的普通值容器。

## lambda 不是神秘语法
```cpp
connect(button, &QPushButton::clicked, this, [this] {
    ++count_;
});
```
方括号指定捕获。`[this]` 保存当前对象的指针；`[value]` 复制变量；`[&value]` 保存引用。如果异步回调发生时局部变量已经离开作用域，引用捕获就危险。优先显式捕获，理解 `[=]` 不会复制 this 所指对象。

连接时的第三个参数是上下文对象，不是 lambda 的一部分。上下文销毁后 Qt 自动断开该连接，但上下文仍活着不代表所有被捕获的外部指针也活着。必须逐个检查依赖对象的生命周期。

## 需要掌握的标准库
先学 `std::vector`、`std::unique_ptr`、`std::optional`、范围 for 和基本算法，能区分值语义与指针语义即可。不要把模板元编程、复杂继承体系当作开始 Qt 的前置条件。UI 线程中的异常不要直接穿过 Qt 事件处理边界；在业务边界捕获并转成可显示的错误。

练习：把计数器拆成 counter.h、counter.cpp、main.cpp，修改 CMake 后重编译。验收：不把函数实现重复放进多个 cpp 引入的头文件；能解释编译错误与链接错误的区别。

## 从单文件走向三个文件

以普通 Counter 类为例，counter.h 中声明类与函数，counter.cpp 包含 counter.h 并实现函数，main.cpp 包含 counter.h 并创建对象。声明告诉编译器“有什么接口”，定义提供实际实现；同一个非 inline 普通函数不能在多个 cpp 各定义一次。

```cpp
// counter.h（这个普通类不依赖 QObject）
#pragma once
class Counter {
public:
    int value() const;
    void increment();
private:
    int value_ = 0;
};
```

```cpp
// counter.cpp
#include "counter.h"
int Counter::value() const { return value_; }
void Counter::increment() { ++value_; }
```

`Counter::` 表示实现属于该类，value 后面的 const 说明读取不会修改普通成员状态。构造函数没有返回类型；初始化列表在进入函数体前初始化成员。`explicit` 防止不希望出现的隐式转换，尤其适合只有一个有效参数的构造函数。

`public` 是外部可用接口，`private` 是类内实现细节；继承 QWidget 用来复用界面能力，不意味着业务数据也必须继承窗口。信号和槽的声明仍遵循 C++ 类型规则，moc 不会替你修复不存在的函数。

## 捕获练习：先说出谁活得更久

按钮回调常保存到未来执行。不要在辅助函数里创建局部 int，再 `[&]` 捕获并连接到长寿命窗口；函数返回后 int 已不存在。需要持续状态时放入窗口成员，需要固定快照时按值捕获，确需共享状态时明确其所有者。

验收：能把已有计数器拆文件后仍正常构建；头文件声明与 cpp 实现签名一致；lambda 捕获列表能逐项解释，不再默认对所有变量使用 `[&]`。
