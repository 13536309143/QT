# 25 · 自动测试：Qt Test、信号和临时数据库

## 测什么才有价值
窗口能启动不代表行为正确。自动测试优先覆盖规则、边界和持久化，交互测试补充关键用户流程。本仓库使用真实 TaskStore 进行内存数据库 CRUD、非法标题、单引号、200/201 长度边界与磁盘重开测试；不是另写一份相似逻辑来证明自己。

QVERIFY 判断条件，QCOMPARE 比较实际值与预期值，数据驱动测试用 _data 函数生成案例。每次测试使用新的命名内存连接，避免测试顺序互相影响。文件测试用 QTemporaryDir，失败退出也自动清理。

## 异步信号测试
QSignalSpy 记录信号；等待异步结果用 spy.wait 或 QTRY_VERIFY，避免固定 sleep 猜测机器速度。示例等待单次定时器 timeout。纯函数测试不需要事件循环，网络和定时器测试则需要让事件得到分发。
```powershell
ctest --test-dir build -C Release --output-on-failure
```
Qt 的测试框架本身会显示 initTestCase 与 cleanupTestCase，不能把它们都算作独立业务需求覆盖。`--smoke` 启动检查也不计为完整交互测试。

练习：添加“数据库路径不可写时 open 返回 false”的案例，再添加标题 trim 后持久化正确的案例。验收：先临时制造一次 bug，确认测试会失败，再修复；重复运行不依赖旧文件。

手工测试仍需验证缩放、Tab 顺序、取消文件对话框、排序后删除、后台运行时关闭窗口。CI 运行在虚拟环境，不等同你的真实桌面和显卡。
参考：[Qt Test](https://doc.qt.io/qt-6.8/qtest-overview.html)。
