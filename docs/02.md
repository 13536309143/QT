# 02 · 开发工具入门：Kit、断点与第一次修改

**前置**：已阅读学习地图。**目标**：分清 Qt、编辑器、编译器和构建目录，完成一次可重复的修改。

## 一张表理解开发环境

| 组件 | 作用 | 本课程使用 |
|---|---|---|
| Qt SDK | 头文件、库、插件、moc 等工具 | sdk/6.8.3/msvc2022_64 |
| 编译器与 Windows SDK | 把 C++ 编译、链接为 Windows 程序 | MSVC 2022 x64 |
| CMake | 组织依赖和构建步骤 | 根目录 CMakeLists.txt |
| 编辑器或 IDE | 编辑、跳转、调试 | 可自行选择 |
| Kit | 一组相互兼容的开发工具配置 | Qt + MSVC + CMake + 调试器 |

仓库脚本不安装 Qt Creator。已有编辑器即可开始；希望使用 Creator 时另行安装，再打开根目录 CMakeLists.txt。不要打开某个 cpp 后期待 IDE 自动知道整个工程。

## 在 Qt Creator 中检查什么

1. 在设置的 Kits 页面检查编译器是否为 MSVC x64，Qt 版本是否指向项目 SDK 的 qmake.exe。
2. 为当前工程选择对应 Kit，构建目录建议用 `build-creator`，与脚本的 `build` 分开。
3. 第一次配置后检查 CMake 输出：Qt 根目录、生成器、编译器必须匹配；不同 Creator 版本的菜单名称可能略有变化。
4. 运行配置中选择 `01_hello`，不要把 `course_tests` 当成日常演示窗口。

若 Creator 没有调试器，先用仓库命令完成构建，再安装或配置适用的 Windows 调试工具。编辑器中的红线来自代码分析器，最终以构建输出为准；两者不一致时检查 Kit 和头文件索引。

## 完成第一次修改

打开 `examples/01_hello/main.cpp`，找到 setWindowTitle，修改标题并保存。运行根目录 build.cmd，之后运行 `scripts\run.cmd 01_hello`。看到新标题才说明“修改 → 保存 → 编译 → 运行”的链条正确；仍显示旧标题时先核对运行的 exe 路径。

构建目录里有缓存、自动生成代码和二进制输出，不能在那里修改源码。Release 用于正常运行，Debug 更便于单步和查看变量；切换配置后检查正在运行的是哪一份程序。

## 断点不是暂停整个世界

在计数器点击处理的 `++count_` 处设置断点。点击加一后查看 count_，执行一次单步，数值应增加一，再继续运行。暂停 GUI 线程期间窗口不响应很正常，不能据此判断死锁。优化后的 Release 可能让变量不可见，因此练习使用 Debug。

实验记录写四项：修改的文件、构建目标、运行路径、观察结果。验收：能找到第一条编译错误；能说清“编辑成功”“构建成功”“运行成功”分别证明什么。
