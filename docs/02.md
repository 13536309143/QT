# 02 · C++ 补课一：值、引用、指针和生命周期

## 先理解内存中的对象
`int count = 0;` 创建一个整数对象，变量名帮助我们找到它。`int &alias = count;` 是同一个对象的别名；`int *ptr = &count;` 则保存对象的地址。引用通常必须绑定有效对象，指针允许是 `nullptr`，解引用前应保证对象仍存在。
```cpp
int count = 10;
int &alias = count;
alias += 1;             // count 变成 11
int *ptr = &count;
if (ptr) *ptr += 1;     // count 变成 12
```
`const QString &name` 常用于只读输入参数，避免不必要的拷贝；返回一个局部变量的引用则会悬空。函数返回值 `QString makeName()` 是正常做法，不要为“省拷贝”牺牲生命周期正确性。

## 栈、堆和 RAII
局部对象离开作用域会自动析构。`new` 创建的对象需要明确所有者。现代 C++ 资源管理优先用 RAII：构造获取资源、析构释放资源。文件句柄、互斥锁和智能指针都可以遵循这个思想。
```cpp
auto service = std::make_unique<Service>(); // 作用域结束自动释放
auto *button = new QPushButton(parent);    // Qt 父对象负责释放
```
不要同时让一个 Qt 父对象和一个长期保存的智能指针独立拥有同一个堆对象，否则销毁顺序可能导致重复释放。不是所有指针都代表所有权；UI 成员变量经常只是观察父对象已经拥有的控件。

## 做一个生命周期推演
用纸画出 `QWidget window`、`new QPushButton(&window)` 和一个普通 `std::vector<int>`。窗口销毁时按钮由父子机制释放，vector 自己在作用域末尾析构。若把按钮地址存到全局变量，窗口销毁后该全局指针不会自动变成空指针，不能再用它。

练习：写一个构造和析构时打印日志的类，分别创建局部对象和 unique_ptr，观察输出次序。验收：能解释为什么返回局部对象地址错误，以及为什么 `delete nullptr` 安全却不能解决悬空指针问题。
