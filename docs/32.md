# 32 · SQLite 进阶：事务、迁移与分页

**前置**：第 31 章；综合项目的数据结构见第 42 章。**目标**：让数据库扩展后仍能打开旧文件，并避免半次导入。

## 事务维护一组操作的整体结果

假设要导入 100 条任务，第 40 条无效。如果需求是“全成功才算成功”，就必须让失败时前 39 条也不留下。先验证格式，再开事务；每次执行检查错误，任何失败 rollback；最后检查 commit 是否成功。不要把关闭进度窗口等同于事务完成。

以下片段假定 db 是当前线程已打开的 QSQLITE 连接，rows 已经过标题规则校验：

```cpp
bool importRows(QSqlDatabase db, const QStringList &rows) {
    if (!db.transaction()) return false;
    QSqlQuery query(db);  // 开事务后创建查询
    if (!query.prepare("INSERT INTO tasks(title) VALUES(?)")) {
        db.rollback(); return false;
    }
    for (const auto &title : rows) {
        query.bindValue(0, title);
        if (!query.exec()) { db.rollback(); return false; }
    }
    query.finish();
    if (db.commit()) return true;
    db.rollback();
    return false;
}
```

真实接口还需返回具体错误；false 只是此处演示控制流。SQL 占位符绑定数据值，不能直接绑定表名或 ORDER BY 的列名；动态列只能从明确白名单选择。

## 从 v1 到 v2 的迁移

1. 在数据库副本上读取 `PRAGMA user_version`；先明确旧库没有版本号时视为什么版本。
2. 开事务，执行 `ALTER TABLE tasks ADD COLUMN priority INTEGER NOT NULL DEFAULT 0`。
3. 为旧数据检查或填充默认值，更新 `PRAGMA user_version = 2`，提交。
4. 未知更高版本停止自动写入，提示升级应用；不要为了能打开而删除表重建。

先备份、再演练迁移失败回滚。TaskDesk 当前版本没有实现这条迁移，本章是扩展步骤，不能声称现有程序已支持 priority 字段。DDL/事务能力与数据库有关，本课程只在 SQLite 范围讨论。

## 分页和索引

少量数据用 LIMIT/OFFSET 易理解；大量翻页时基于稳定排序键继续读取，例如 `WHERE id > ? ORDER BY id LIMIT ?`。同时按其他字段排序时需要组合游标和确定的并列顺序。索引应围绕真实 WHERE/ORDER BY 设计，用 EXPLAIN QUERY PLAN 检查，不盲目为每列建索引。

每个线程创建、使用并移除自己的数据库连接。QSqlDatabase 的拷贝是连接句柄，不是独立物理连接；随手复制给 worker 并不能跨线程安全查询。

验收：批次中间失败不留半批记录；旧数据库升级后数据保留；未知版本不会被覆盖。练习答案要点：版本更新与结构修改放同一事务，查询和模型销毁后再 removeDatabase。

参考：[QSqlDatabase](https://doc.qt.io/qt-6.8/qsqldatabase.html)、[QSqlQuery](https://doc.qt.io/qt-6.8/qsqlquery.html)。

## 数据库与 TaskDesk：参数、结果与时机

### `QSqlDatabase::addDatabase(driver, name)`

- **参数怎样填**：如 QSQLITE 和唯一连接名。
- **作用与返回结果**：返回连接句柄。
- **调用时机与易错点**：同名会影响旧连接；一个句柄拷贝不是新建独立连接。

### `setDatabaseName(path) / open()`

- **参数怎样填**：路径或 :memory:；打开无参数。
- **作用与返回结果**：设置目标 / open 返回 bool。
- **调用时机与易错点**：失败检查 lastError；SQLite 内存库退出即丢，不能当持久化。

### `QSqlQuery::prepare(sql)`

- **参数怎样填**：含 ? 或命名占位符的 SQL。
- **作用与返回结果**：返回 bool。
- **调用时机与易错点**：准备也会失败；表名和排序字段不能作为普通值占位符绑定。

### `addBindValue(value) / bindValue(index, value)`

- **参数怎样填**：顺序追加值或按位置更新值。
- **作用与返回结果**：把值交给驱动，返回 void。
- **调用时机与易错点**：与 SQL 中占位符顺序对应，不通过 arg 拼接用户标题。

### `QSqlQuery::exec()`

- **参数怎样填**：执行已准备语句，或传 SQL 的重载。
- **作用与返回结果**：返回 bool。
- **调用时机与易错点**：成功不代表一定匹配到某一行；更新/删除还检查受影响行数。

### `QSqlQuery::next() / value(column)`

- **参数怎样填**：推进到下一条结果 / 当前行列号。
- **作用与返回结果**：返回 bool / QVariant。
- **调用时机与易错点**：必须先 next 成功再读 value；不要把查询失败当作合法空结果。

### `numRowsAffected()`

- **参数怎样填**：无参数。
- **作用与返回结果**：返回写操作影响行数，驱动无法提供时可有特殊值。
- **调用时机与易错点**：课程的单主键更新要求 1 行，0 行表示目标可能已经不存在。

### `transaction() / commit() / rollback()`

- **参数怎样填**：数据库连接成员，无参数。
- **作用与返回结果**：均返回 bool。
- **调用时机与易错点**：每个结果都检查；业务整批成功才提交，失败回滚，不弹成功提示。

### `QSqlQuery::finish()`

- **参数怎样填**：无参数。
- **作用与返回结果**：结束活动结果集，保留查询对象。
- **调用时机与易错点**：有些数据库提交前需结束查询；销毁连接前还需让模型和查询退出作用域。

### `QSqlDatabase::removeDatabase(name)`

- **参数怎样填**：连接名。
- **作用与返回结果**：移除命名连接。
- **调用时机与易错点**：不能仍有活动 query/model/外部句柄引用该连接；先销毁使用者。

### `TaskStore::open(path)`

- **参数怎样填**：课程仓储自定义接口。
- **作用与返回结果**：返回 bool；打开并建表。
- **调用时机与易错点**：不是 Qt 自带函数；失败用 store.error 读课程保存的错误。

### `TaskStore::add(title)`

- **参数怎样填**：候选标题。
- **作用与返回结果**：trim 后校验 1~200 UTF-16 单元，成功写入返回 true。
- **调用时机与易错点**：UI 通过验证不代表其他调用者不会绕过，仓储仍要保护规则。

### `TaskStore::complete(id, done) / remove(id)`

- **参数怎样填**：稳定主键与目标完成状态，或删除主键。
- **作用与返回结果**：返回 bool，要求真正影响一行。
- **调用时机与易错点**：id 不是排序后的可见行号；操作后刷新展示并处理失败。
