# 41 · 进阶发布：日志、翻译与可交付检查

**前置**：第 38、40 章；仓库协作可结合第 45 章学习。**目标**：让别人拿到程序后能使用、定位问题和升级。

## 日志先服务于问题定位

```cpp
#include <QLoggingCategory>
Q_LOGGING_CATEGORY(lcStore, "course.store")
// 在数据库操作失败处使用：
// qCWarning(lcStore) << "保存失败" << errorCode;
```

分类日志可以按模块筛选。记录动作、错误类别、请求编号和耗时，避免记录密码、令牌或完整私人数据。需要写文件时指定用户可写目录，限制大小和保留数量，并考虑多线程写入同步；上述片段只声明分类，不自动生成日志文件。

## 国际化是一条完整流程

用 tr 或 QCoreApplication::translate 标记可翻译文本，lupdate 提取到 ts，翻译后用 lrelease 生成 qm，启动时通过 QTranslator.load 安装翻译器。翻译器对象要比使用它的界面活得久，不能局部创建后立即返回。

运行时切换语言还要处理 LanguageChange 并更新已有控件；C++ 手写界面不会因为调用 installTranslator 就自动执行所有 setText。完整句子用占位符，不把“完成”和数量拆开拼接；数字、日期用 QLocale 按用户地区展示。

## 升级前要问的数据问题

程序版本与数据库格式版本分别记录。更新程序之前明确备份、迁移、未知版本处理和失败恢复；不要把应用升级实现为删除用户数据目录。分发目录放 exe 与运行依赖，用户数据留在 QStandardPaths 指定位置。

## 一份真正可交付的目录

包含程序、需要的 DLL/插件/QML、运行库安装说明、版本号、第三方通知、简短使用说明。README 写清系统架构、数据位置、已知限制和反馈时需要的版本信息。windeployqt 负责收集 Qt 依赖，不会替你验证每条业务流程或所有许可证义务。

实操：部署 15_settings、16_tcp，在不含 Qt SDK 路径的终端启动；测试中文路径、设置恢复、消息回显和关闭。额外在干净 Windows 环境检查运行库与图形后端；没有该环境就记录“尚未验证”。

验收：新用户知道从哪启动、如何退出、数据在哪；日志能定位失败且不泄露私人输入；语言切换后没有旧语言残留。串口和多媒体仍是选修路线，需另装模块与设备验证，不属于当前可运行示例承诺。

参考：[翻译流程](https://doc.qt.io/qt-6.8/i18n-source-translation.html)、[分类日志](https://doc.qt.io/qt-6.8/qloggingcategory.html)。

## QML、测试与工程诊断：参数、结果与时机

### `QQmlApplicationEngine::loadFromModule(uri, typeName)`

- **参数怎样填**：课程使用 Course 与 Main。
- **作用与返回结果**：加载模块中的根类型，返回 void。
- **调用时机与易错点**：配置 URI、资源名或 required 属性错误会使创建失败，连接 objectCreationFailed 处理退出。

### `Q_PROPERTY(... READ ... NOTIFY ...)`

- **参数怎样填**：这是元对象声明宏，不是运行时函数。
- **作用与返回结果**：使属性可被读取并通知变化。
- **调用时机与易错点**：NOTIFY 的发送必须由你的代码保证；getter 不应执行长时间磁盘或网络工作。

### `Counter::increment()`

- **参数怎样填**：课程自定义 Q_INVOKABLE，无参数。
- **作用与返回结果**：改变 count 并发 countChanged。
- **调用时机与易错点**：Q_INVOKABLE 只暴露调用能力，不自动启动线程。

### `QSignalSpy(sender, signal)`

- **参数怎样填**：被观察对象和信号指针。
- **作用与返回结果**：创建信号记录器，用 isValid 检查。
- **调用时机与易错点**：尽量在动作前创建，以免错过已经同步发出的信号。

### `QSignalSpy::wait(timeout)`

- **参数怎样填**：最长等待毫秒数。
- **作用与返回结果**：在超时内收到新信号返回 true。
- **调用时机与易错点**：先检查已有数量再 wait，避免信号已发生却继续等待下一次。

### `QVERIFY(expr) / QCOMPARE(actual, expected)`

- **参数怎样填**：测试条件或实际值与期望值。
- **作用与返回结果**：失败记录上下文并结束当前测试函数。
- **调用时机与易错点**：它们是测试宏，不是给真实用户处理错误的界面。

### `QTRY_VERIFY(expr) / QTRY_COMPARE(actual, expected)`

- **参数怎样填**：可在事件循环中逐步成立的条件。
- **作用与返回结果**：重试直到成立或超时。
- **调用时机与易错点**：不是无限等待；比固定 sleep 更能适应不同机器速度。

### `QTest::mouseClick(widget, button)`

- **参数怎样填**：控件与鼠标按钮等参数。
- **作用与返回结果**：模拟交互。
- **调用时机与易错点**：应测真实窗口的用户结果，而不是仅证明 Qt 自带按钮能发信号。

### `QLoggingCategory(...) / qCWarning(category)`

- **参数怎样填**：日志分类和输出表达式。
- **作用与返回结果**：按类别组织诊断。
- **调用时机与易错点**：不会自动写日志文件、轮转或删除敏感信息，仍需明确日志策略。

### `QProcess 等外部工具`

- **参数怎样填**：本课程部署脚本实际调用 windeployqt，而非此处启动 Qt 类。
- **作用与返回结果**：部署命令收集 DLL、插件和 QML。
- **调用时机与易错点**：工具返回成功不证明所有 GPU、驱动、用户输入路径和第三方许可均已验收。

**阅读任务**：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 [完整函数手册](API.md#qmltest) 继续查阅。
