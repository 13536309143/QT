# 41 · 进阶发布：日志、翻译与可交付检查

**前置**：第 38、40 章；仓库协作可结合第 45 章学习。**目标**：让别人拿到程序后能使用、定位问题和升级。

## 日志先服务于问题定位

```cpp
#include <QLoggingCategory>
Q_LOGGING_CATEGORY(lcStore, "course.store")
// 在数据库操作失败处使用：
// qCWarning(lcStore) << "保存失败" << errorCode;
```

分类日志可以按模块筛选。记录动作、错误类别、请求编号和耗时，避免记录密码、令牌或完整私人数据。需要写文件时指定用户可写目录，限制大小和保留数量，并考虑多线程写入同步；上述片段只声明分类，不自动生成日志文件。

## 国际化是一条完整流程

用 tr 或 QCoreApplication::translate 标记可翻译文本，lupdate 提取到 ts，翻译后用 lrelease 生成 qm，启动时通过 QTranslator.load 安装翻译器。翻译器对象要比使用它的界面活得久，不能局部创建后立即返回。

运行时切换语言还要处理 LanguageChange 并更新已有控件；C++ 手写界面不会因为调用 installTranslator 就自动执行所有 setText。完整句子用占位符，不把“完成”和数量拆开拼接；数字、日期用 QLocale 按用户地区展示。

## 升级前要问的数据问题

程序版本与数据库格式版本分别记录。更新程序之前明确备份、迁移、未知版本处理和失败恢复；不要把应用升级实现为删除用户数据目录。分发目录放 exe 与运行依赖，用户数据留在 QStandardPaths 指定位置。

## 一份真正可交付的目录

包含程序、需要的 DLL/插件/QML、运行库安装说明、版本号、第三方通知、简短使用说明。README 写清系统架构、数据位置、已知限制和反馈时需要的版本信息。windeployqt 负责收集 Qt 依赖，不会替你验证每条业务流程或所有许可证义务。

实操：部署 15_settings、16_tcp，在不含 Qt SDK 路径的终端启动；测试中文路径、设置恢复、消息回显和关闭。额外在干净 Windows 环境检查运行库与图形后端；没有该环境就记录“尚未验证”。

验收：新用户知道从哪启动、如何退出、数据在哪；日志能定位失败且不泄露私人输入；语言切换后没有旧语言残留。串口和多媒体仍是选修路线，需另装模块与设备验证，不属于当前可运行示例承诺。
