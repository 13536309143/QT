# 27 · 多线程：后台任务、取消和退出

## 先确定为什么要线程
网络本身通常可异步完成，不必每个 HTTP 请求都开线程。CPU 密集计算、阻塞式第三方库和大量解析才常需要后台执行。QWidget 只能在 GUI 线程使用，后台完成结果通过信号传回来。

QThread 对象通常活在创建它的线程，而 run 管理的是另一个执行线程。把 Worker QObject moveToThread 后，它的槽才会按连接类型在对应线程运行。带父对象的 Worker 不能直接搬到另一个线程；示例先创建无父 Worker，再移动。

## 阅读 08_worker 的退出路径
start 创建 Worker；started 触发 run；progress 排队更新进度条；finished 请求线程退出；thread finished 安排 Worker 删除。窗口析构时先 requestInterruption，再 quit 和 wait，确保线程不会带着仍被使用的对象离开。

本例 finished → thread.quit 使用 DirectConnection 是有意的：quit 是线程安全的退出请求，不是 GUI 更新。关闭窗口时 GUI 线程可能正在 wait，不能依赖排队到 GUI 线程的 quit 才让后台结束。这个特例不能推广到任意对象方法。

## 取消是协作行为
requestInterruption 只是标记，后台必须定期检查。长时间阻塞 I/O 还需要超时或可取消 API。若把 cancel 槽排队到一个正在执行长循环的 Worker，那个槽可能要等循环结束才处理，因此示例直接用线程安全的中断请求。

不要使用 terminate 强行杀线程，资源可能无法正常释放。示例线程每 20ms 检查一次，关闭等待短；实际程序应设计有界退出策略。共享可变数据才需要 QMutex 等同步；优先通过消息传值减少共享。练习：开始、取消、再次开始，然后运行中关闭窗口。验收：没有 QThread destroyed while running，没有跨线程控件警告。
参考：[线程与 QObject](https://doc.qt.io/qt-6.8/threads-qobject.html)。

## 配套完整源码

在根工程构建本章目标：`08_worker`。以下是仓库内同一份文件，修改请到 examples 目录。

### main.cpp

```cpp
#include <QtWidgets>
class Worker : public QObject {
    Q_OBJECT
public slots:
    void run() {
        for(int i=0;i<=100;++i) {
            if(QThread::currentThread()->isInterruptionRequested()) break;
            QThread::msleep(20); // 仅模拟后台耗时工作，不在 GUI 线程 sleep
            emit progress(i);
        }
        emit finished();
    }
signals: void progress(int value); void finished();
};
class Window : public QWidget {
public:
    Window() {
        auto *layout=new QVBoxLayout(this); auto *bar=new QProgressBar(this);
        auto *start=new QPushButton(QStringLiteral("开始"),this);
        auto *cancel=new QPushButton(QStringLiteral("取消"),this);
        layout->addWidget(bar); layout->addWidget(start); layout->addWidget(cancel);
        connect(start,&QPushButton::clicked,this,[=] {
            if(thread_.isRunning()) return;
            bar->setValue(0); start->setEnabled(false);
            auto *worker=new Worker; worker->moveToThread(&thread_);
            connect(&thread_,&QThread::started,worker,&Worker::run);
            connect(worker,&Worker::progress,bar,&QProgressBar::setValue);
            connect(worker,&Worker::finished,&thread_,&QThread::quit,Qt::DirectConnection);
            connect(&thread_,&QThread::finished,worker,&QObject::deleteLater);
            thread_.start();
        });
        connect(&thread_,&QThread::finished,this,[=] { start->setEnabled(true); });
        connect(cancel,&QPushButton::clicked,this,[this] { thread_.requestInterruption(); });
    }
    ~Window() override { thread_.requestInterruption(); thread_.quit(); thread_.wait(); }
private: QThread thread_;
};
int main(int argc,char **argv) {
    QApplication app(argc,argv); Window w; w.show();
    if(app.arguments().contains("--smoke")) QTimer::singleShot(150,&app,&QCoreApplication::quit);
    return app.exec();
}
#include "main.moc"
```

## 线程、HTTP 与 TCP：参数、结果与时机

### `QThread::start() / isRunning()`

- **参数怎样填**：启动可指定优先级；查询无参数。
- **作用与返回结果**：启动线程 / 返回 bool。
- **调用时机与易错点**：线程开始不等于业务已经完成；重复点击前检查实际状态。

### `requestInterruption() / isInterruptionRequested()`

- **参数怎样填**：无参数。
- **作用与返回结果**：发协作取消请求 / 查询 bool。
- **调用时机与易错点**：请求不会强杀线程，工作代码需周期检查，阻塞操作还需有界超时。

### `QThread::quit() / wait()`

- **参数怎样填**：请求事件循环结束 / 可指定等待上限。
- **作用与返回结果**：quit 返回 void，wait 返回 bool。
- **调用时机与易错点**：quit 不会中断正在执行的长循环；GUI 上长时间 wait 会冻结界面。

### `QNetworkAccessManager::get(request)`

- **参数怎样填**：QNetworkRequest。
- **作用与返回结果**：返回 QNetworkReply 指针，网络异步继续。
- **调用时机与易错点**：调用返回不是请求完成；reply 生命周期与 finished/error 处理必须清楚。

### `QNetworkRequest::setTransferTimeout(ms)`

- **参数怎样填**：无数据传输超时毫秒数。
- **作用与返回结果**：设置传输超时策略。
- **调用时机与易错点**：不等同于所有情况下的总时限；课程另外设 singleShot 总时限。

### `QNetworkReply::attribute(code)`

- **参数怎样填**：如 HttpStatusCodeAttribute。
- **作用与返回结果**：返回 QVariant 状态信息。
- **调用时机与易错点**：无 HTTP 响应时可能没有状态码，不能把 0 当作正常 HTTP 状态。

### `QNetworkReply::error() / abort()`

- **参数怎样填**：查询或主动终止。
- **作用与返回结果**：返回错误枚举 / void。
- **调用时机与易错点**：abort 也会进入结束路径；恢复按钮和释放 reply 不应只写在成功分支。

### `QTcpServer::listen(address, port)`

- **参数怎样填**：监听地址和端口；0 请求系统分配。
- **作用与返回结果**：返回 bool；成功后用 serverPort 取实际端口。
- **调用时机与易错点**：本例只用 LocalHost；不要无意改为 Any 后把教学服务开放给局域网。

### `nextPendingConnection()`

- **参数怎样填**：无参数。
- **作用与返回结果**：返回待处理服务端 socket 指针。
- **调用时机与易错点**：在 newConnection 后处理；为每条连接保留独立解析器，并在断开后销毁。

### `QTcpSocket::connectToHost(address, port)`

- **参数怎样填**：地址与端口。
- **作用与返回结果**：启动异步连接，返回 void。
- **调用时机与易错点**：等待 connected 或 errorOccurred；不要在 GUI 中 waitForConnected 阻塞。

### `bytesAvailable() / read(maxSize)`

- **参数怎样填**：可读字节数查询或最大读取量。
- **作用与返回结果**：返回 qint64 / QByteArray。
- **调用时机与易错点**：一次读取不保证整帧，解析器必须保存尾部残留数据。

### `setReadBufferSize(bytes)`

- **参数怎样填**：最大接收缓冲字节数，0 有无限制语义。
- **作用与返回结果**：限制 socket 接收缓冲。
- **调用时机与易错点**：业务拆帧缓存、发送队列和日志也需分别设上限。

### `LineProtocol::feed(bytes, lines)`

- **参数怎样填**：自定义解析器；输入字节和输出完整行列表。
- **作用与返回结果**：返回 bool，false 表示超过帧上限。
- **调用时机与易错点**：按 LF 取帧，残留半帧保存在内部；false 时调用方终止连接，不把损坏数据当正常消息。

**阅读任务**：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 [完整函数手册](API.md#async) 继续查阅。
