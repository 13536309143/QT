# 31 · SQLite：连接、SQL、绑定和事务

## 一个数据库文件的结构
SQLite 不需要单独数据库服务，适合本地工具。QSqlDatabase 管理连接，QSqlQuery 执行 SQL，QSqlError 解释失败。驱动 QSQLITE 是 Qt 插件，开发机运行正常但分发后失败时应检查 sqldrivers 插件部署。

运行 10_sql，数据库使用 :memory:，退出即消失。CREATE TABLE 创建结构，INSERT 插入记录，SELECT 返回行，query.next 才把游标移动到结果。不能在 next 之前直接 value 获取第一行。

## 一律绑定外部数据
```cpp
query.prepare("INSERT INTO tasks(title) VALUES(:title)");
query.bindValue(":title", title);
if (!query.exec()) { /* 显示 query.lastError().text() */ }
```
不要用字符串拼接标题到 SQL。绑定解决引号转义并隔离数据与 SQL 语句结构。表名、列名不能用普通值占位符替代，动态列名应从固定白名单选择。

## 事务和连接生命期
多条操作需要一起成功时，先 transaction，任意一步失败 rollback，全部成功 commit，并检查三个阶段结果。连接只能在满足 Qt 线程规则的线程使用，后台数据库工作应创建自己的连接；不能复制 QSqlDatabase 句柄就当作线程隔离。

removeDatabase 前必须销毁相关 query/model 和句柄。TaskStore 析构先关闭连接，清空自身句柄，再移除命名连接；窗口在 Store 之前销毁，避免模型持有连接。应用扩展时不要让查询逃出仓储的有效范围。

练习：一次事务插入两条记录，故意让第二条违反约束，验证第一条也被回滚。验收：标题含单引号和中文仍正常；重复主键错误清楚可见。
参考：[QSqlQuery](https://doc.qt.io/qt-6.8/qsqlquery.html)。

## 配套完整源码

在根工程构建本章目标：`10_sql`。以下是仓库内同一份文件，修改请到 examples 目录。

### main.cpp

```cpp
#include <QtCore>
#include <QtSql>
int main(int argc,char **argv) {
    QCoreApplication app(argc,argv);
    auto db=QSqlDatabase::addDatabase("QSQLITE"); db.setDatabaseName(":memory:");
    if(!db.open()) { qCritical()<<db.lastError().text(); return 1; }
    QSqlQuery query(db);
    if(!query.exec("CREATE TABLE tasks(id INTEGER PRIMARY KEY, title TEXT NOT NULL)")) return 2;
    query.prepare("INSERT INTO tasks(title) VALUES(:title)");
    query.bindValue(":title",QStringLiteral("带引号的任务 ' Qt"));
    if(!query.exec()) { qCritical()<<query.lastError().text(); return 3; }
    if(!query.exec("SELECT id,title FROM tasks ORDER BY id")) return 4;
    while(query.next()) qInfo()<<query.value(0).toInt()<<query.value(1).toString();
    return 0;
}
```

## 数据库与 TaskDesk：参数、结果与时机

### `QSqlDatabase::addDatabase(driver, name)`

- **参数怎样填**：如 QSQLITE 和唯一连接名。
- **作用与返回结果**：返回连接句柄。
- **调用时机与易错点**：同名会影响旧连接；一个句柄拷贝不是新建独立连接。

### `setDatabaseName(path) / open()`

- **参数怎样填**：路径或 :memory:；打开无参数。
- **作用与返回结果**：设置目标 / open 返回 bool。
- **调用时机与易错点**：失败检查 lastError；SQLite 内存库退出即丢，不能当持久化。

### `QSqlQuery::prepare(sql)`

- **参数怎样填**：含 ? 或命名占位符的 SQL。
- **作用与返回结果**：返回 bool。
- **调用时机与易错点**：准备也会失败；表名和排序字段不能作为普通值占位符绑定。

### `addBindValue(value) / bindValue(index, value)`

- **参数怎样填**：顺序追加值或按位置更新值。
- **作用与返回结果**：把值交给驱动，返回 void。
- **调用时机与易错点**：与 SQL 中占位符顺序对应，不通过 arg 拼接用户标题。

### `QSqlQuery::exec()`

- **参数怎样填**：执行已准备语句，或传 SQL 的重载。
- **作用与返回结果**：返回 bool。
- **调用时机与易错点**：成功不代表一定匹配到某一行；更新/删除还检查受影响行数。

### `QSqlQuery::next() / value(column)`

- **参数怎样填**：推进到下一条结果 / 当前行列号。
- **作用与返回结果**：返回 bool / QVariant。
- **调用时机与易错点**：必须先 next 成功再读 value；不要把查询失败当作合法空结果。

### `numRowsAffected()`

- **参数怎样填**：无参数。
- **作用与返回结果**：返回写操作影响行数，驱动无法提供时可有特殊值。
- **调用时机与易错点**：课程的单主键更新要求 1 行，0 行表示目标可能已经不存在。

### `transaction() / commit() / rollback()`

- **参数怎样填**：数据库连接成员，无参数。
- **作用与返回结果**：均返回 bool。
- **调用时机与易错点**：每个结果都检查；业务整批成功才提交，失败回滚，不弹成功提示。

### `QSqlQuery::finish()`

- **参数怎样填**：无参数。
- **作用与返回结果**：结束活动结果集，保留查询对象。
- **调用时机与易错点**：有些数据库提交前需结束查询；销毁连接前还需让模型和查询退出作用域。

### `QSqlDatabase::removeDatabase(name)`

- **参数怎样填**：连接名。
- **作用与返回结果**：移除命名连接。
- **调用时机与易错点**：不能仍有活动 query/model/外部句柄引用该连接；先销毁使用者。

### `TaskStore::open(path)`

- **参数怎样填**：课程仓储自定义接口。
- **作用与返回结果**：返回 bool；打开并建表。
- **调用时机与易错点**：不是 Qt 自带函数；失败用 store.error 读课程保存的错误。

### `TaskStore::add(title)`

- **参数怎样填**：候选标题。
- **作用与返回结果**：trim 后校验 1~200 UTF-16 单元，成功写入返回 true。
- **调用时机与易错点**：UI 通过验证不代表其他调用者不会绕过，仓储仍要保护规则。

### `TaskStore::complete(id, done) / remove(id)`

- **参数怎样填**：稳定主键与目标完成状态，或删除主键。
- **作用与返回结果**：返回 bool，要求真正影响一行。
- **调用时机与易错点**：id 不是排序后的可见行号；操作后刷新展示并处理失败。
