# 53 · OpenGL 工程化：交互、离屏渲染、调试与清理

## 一、把交互状态与 GPU 调用分开

按钮点击、滑块变化或鼠标拖动只改变 angle、缩放等普通 C++ 状态，然后 update。paintGL 读取当前状态生成一帧。这样业务输入不依赖 GL 此刻是否 current，也不会在每次鼠标移动时重复建立 shader。

动画用 QElapsedTimer 测实际 dt，例如角速度为每秒 30 度时，增量为 30*dt。定时器用于请求下一帧，不是精确时钟；窗口遮挡或系统繁忙后，固定“每次加一度”的动画会改变速度。长暂停后可限制过大的 dt，避免相机突然跳动。

## 二、QOpenGLWidget 的默认目标不是固定 0

QOpenGLWidget 先渲染到内部 framebuffer，再由 Qt 合成。操作自建 FBO 后需要恢复 defaultFramebufferObject()，不要写死 glBindFramebuffer(...,0)。Qt 可能因 resize 重建内部 FBO，不能永久缓存旧编号。

QOpenGLFramebufferObject 用来进行离屏绘制，如缩略图、后处理和选取。建立时指定目标像素尺寸与格式，检查 isValid；bind 返回 bool；绘制完恢复正确目标以及 viewport。它的存在不会自动保存截图文件，读回 QImage 后还要检查保存结果。

离屏缓冲尺寸与显示控件可以不同。先把绘制函数设计为“接收目标尺寸并绘制场景”，避免每个绘制函数偷偷读取窗口逻辑 width。这样之后做高分辨率导出时更容易复用。

## 三、用可解释的顺序排查黑屏

1. 检查 context 是否有效、实际版本和 GL vendor/renderer。
2. 只清屏为明显颜色，确认目标与合成路径工作。
3. 检查 shader 编译与链接日志，暂时输出固定片元颜色。
4. 检查 VAO、VBO 和 attribute 的类型、offset、stride。
5. 暂时去掉投影，确认三角形在裁剪范围内。
6. 再加入深度、剔除、混合和纹理，逐项比较。

QOpenGLDebugLogger 可接收驱动调试消息，但需要相应上下文支持；先请求 DebugContext，initialize 后检查返回值。glGetError 也只是一种局部诊断工具，不是性能分析器，不能靠每帧打印海量日志修复状态错误。

## 四、错误检查不应只看一个 bool

addShader...、link、buffer.create 和 bind 都有可检查的结果。分配 GPU buffer 的某些封装调用返回 void，这不代表永不失败；开发时结合调试输出、实际绘制和资源尺寸判断。错误发生后应保留明确状态，避免 ready_=true 让后续继续使用半初始化对象。

截图自检同样有边界：中心与角落不同可确认本例不是纯清屏，但不能证明颜色空间、所有顶点和所有缩放条件完全正确。GPU CI 不可用时，记录“未运行”并保留人工步骤，不能用 offscreen 启动退出代替图形验证。

## 五、资源与线程的底线

GL handle 与创建它的上下文或共享组有关；C++ 指针仍活着不代表 handle 可在任意上下文使用。工作线程可解析模型与图片，上传和绘制则需要明确 current 的上下文和同步设计。初学项目先保持单渲染线程，再优化，不将共享 context 当作无锁共享所有 GL 状态。

关闭时停止生产新任务，在合适上下文下释放 texture、FBO、VAO、VBO 和 program。资源销毁顺序按实际依赖安排，清理路径需要覆盖初始化只成功一半的情况。多次打开、缩放、关闭应重复验证，不能只运行一次就断言没有泄漏。

实验：给示例加入旋转滑块；连续 resize；遮挡后恢复；导出一张离屏图；故意制造 shader 拼写错误。验收时分别记录正常路径和故障提示，并说明哪些检查需要真实 GPU 环境。
