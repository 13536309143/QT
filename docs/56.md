# 56 · Vulkan 三角形进阶：shader、buffer 与图形管线

本章是从清屏到绘制的实施路线与接口详解。18_vulkan 当前只提供清屏；下面片段需要你在渲染器增加成员、创建与释放函数，不能把未完成的片段当作已经可运行的三角形程序。

## 一、先用无顶点缓冲版本隔离问题

第一次三角形可以用顶点 shader 的 gl_VertexIndex 索引三个常量位置。这样先不涉及 VkBuffer 与显存选择，便于只验证 pipeline、shader 和 draw。后续再把位置迁移到 vertex buffer，而不是一次同时引入所有概念。

```glsl
#version 450
layout(location=0) out vec3 color;
vec2 positions[3] = vec2[](vec2(-0.7,-0.6), vec2(0.7,-0.6), vec2(0,0.7));
vec3 colors[3] = vec3[](vec3(1,0,0), vec3(0,1,0), vec3(0,0,1));
void main() {
    gl_Position=vec4(positions[gl_VertexIndex],0,1);
    color=colors[gl_VertexIndex];
}
```

片元阶段对应 location=0 的 vec3 输入与 vec4 输出。使用 SDK 工具如 glslc 将两个阶段分别编译为 SPIR-V；本教程的轻量头文件环境并不附带 glslc。编译命令例如 `glslc triangle.vert -o triangle.vert.spv`，成功生成文件后仍需检查目标 API 与运行设备要求。

## 二、shader module 的接口契约

读取 .spv 时检查 QFile 打开、长度为 4 的倍数以及实际读取完整。准备 uint32_t 对齐的存储，把字节复制进去，再给 VkShaderModuleCreateInfo 的 codeSize 传字节数，pCode 传对齐的 uint32_t 指针。不要假定任意 QByteArray 指针都满足所有原生接口对齐要求。

vkCreateShaderModule 的输入是 device、createInfo、可选 allocator、输出 handle 地址；返回 VkResult，成功才使用 handle。VkPipelineShaderStageCreateInfo 指定 stage、module、入口名 "main"。shader module 和 pipeline 是不同对象，不能把 VkShaderModule 当作可直接绘制的 program。

## 三、图形管线每一项怎么填

| 状态 | 最小三角形的决定 | 为什么不能省略思考 |
|---|---|---|
| shader stages | vertex + fragment，接口 location 匹配 | 单阶段编译成功不证明管线接口兼容 |
| vertex input | 无 VBO 版本 binding/attribute 数为 0 | 加 VBO 后必须声明格式与跨度 |
| input assembly | TRIANGLE_LIST，primitive restart 关闭 | 顶点数量与拓扑共同决定图元 |
| viewport/scissor | 使用当前目标尺寸或动态状态 | 动态状态声明后必须在命令中设置 |
| rasterization | 填充、lineWidth=1，初期不剔除 | 正反面与坐标方向错会让面消失 |
| multisample | 与 Qt pass 的 sampleCountFlagBits 一致 | 单采样与 MSAA 不能随意混用 |
| depth/stencil | 首个 2D 三角形可关闭测试 | 有附件不表示必须启用深度写入 |
| color blend | 一个颜色附件，RGBA 写入开启 | 写入掩码为 0 会看起来没有输出 |
| pipeline layout | 无 descriptor、无 push constant 的空布局 | 后续资源绑定必须与 layout 一致 |
| render pass/subpass | Qt 的 defaultRenderPass，subpass=0 | 不能拿不兼容 pass 的 pipeline 绘制 |

先分别零初始化所有结构体并设置 sType。vkCreatePipelineLayout 和 vkCreateGraphicsPipelines 都检查 VkResult；部分失败后的清理也应覆盖已经成功创建的对象。不要只把 output handle 初始化成 0 就认定创建成功。

## 四、在正确位置录制 draw

在第 55 章 beginRenderPass 与 endRenderPass 之间，绑定 VK_PIPELINE_BIND_POINT_GRAPHICS 的 pipeline；若使用动态 viewport/scissor，调用 vkCmdSetViewport 和 vkCmdSetScissor；再 vkCmdDraw(command,3,1,0,0)。

vkCmdDraw 的参数依次是 command、vertexCount、instanceCount、firstVertex、firstInstance。此时不是上传三条记录，只是告诉 GPU 在已配置管线下执行绘制。命令录制没有 VkResult 返回，调试要依赖验证层和完整的状态准备。

## 五、再加入真实顶点缓冲

VkBufferCreateInfo 指定 size（字节）、usage=VERTEX_BUFFER 和 sharingMode；vkCreateBuffer 只创建对象，尚未分配可用存储。vkGetBufferMemoryRequirements 返回 size、alignment 和 memoryTypeBits；选择同时满足允许位与所需内存属性的类型，再 vkAllocateMemory、vkBindBufferMemory。

不要直接假定任意 hostVisibleMemoryIndex 都与某个资源的 memoryTypeBits 兼容。上传时 map 允许的范围、复制数据；非 HOST_COHERENT 内存需要符合 nonCoherentAtomSize 等约束的 flush。unmap 不自动等于为所有非一致性内存完成刷新。

迁移后的 layout 指定 binding 0 的 stride、每个 attribute 的 location/format/offset。vec2 位置可选 R32G32_SFLOAT，vec3 颜色可选 R32G32B32_SFLOAT；offset 与第 51 章同样按字节算。绘制前 vkCmdBindVertexBuffers，再保持 vkCmdDraw 的顶点数为 3。

## 六、资源何时释放

设备级 vertex buffer 与其 memory 在 releaseResources 路径处理；绑定依赖的对象先停止使用，再销毁 buffer，最后 free 对应 memory。与 pass、格式或尺寸关联的 pipeline 应按具体设计在交换链重建时检查或重建。不能销毁 GPU 仍在使用的对象。

验收顺序：固定颜色三角形 → 插值颜色 → VBO 替代常量顶点 → resize 后仍正确 → 验证层无错误。每次只加一个阶段，并记录本章还没实现的部分。
