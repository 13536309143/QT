# 39 · 性能与内存：先测量，再优化

**前置**：第 21、27、38 章。**目标**：找到真正耗时的位置，并区分慢、阻塞和泄漏。

## 四类问题不要混在一起

启动慢可能来自大量读取和初始化；界面卡顿常是 GUI 线程长任务；内存上升可能来自缓存或未结束的请求；数据库慢可能是全表扫描。先描述观察到的现象、数据量和耗时，再决定工具。

```cpp
QElapsedTimer timer;
timer.start();
// 在这里执行一次待测操作，例如加载 10000 条测试记录。
qInfo() << "加载耗时(ms):" << timer.elapsed();
```

记录机器、构建配置、数据量、冷启动或热启动。Debug 的耗时不能直接代表 Release。微秒级操作容易受系统调度影响，不把一次测量当作绝对结论；涉及事件循环的总耗时还应包括异步完成时刻。

## 优先处理数量级

每次按键遍历十万行，比一次 QString 拷贝更值得关注。数据库筛选下推 SQL、按需加载、合并进度信号、批量更新模型，通常比手工优化小表达式更有效。大量表格行使用模型与委托，不创建十万个 QWidget。

设置定时器 1ms 不保证一秒回调一千次，忙时可能延迟；反复 processEvents 可能引入重入，不能当作性能方案。异步化也不一定使总计算更快，它首先改善界面响应，并可能增加同步成本。

## 内存所有权检查

检查无父对象的堆 QObject、未 deleteLater 的网络 reply、不断增长的日志、未消费的 queued 信号。QPointer 观察销毁，不释放对象；shared_ptr 引用环不会因窗口关闭自动消失。缓存应说明容量和淘汰策略。

任务管理器中的进程内存不立即下降，不足以证明泄漏；分配器和缓存可能保留内存。用重复执行后的稳定趋势、对象计数和合适的分析器进一步判断，不凭一张截图下结论。

## 动手实验

为 TaskDesk 的副本生成 100、10000、50000 条测试任务，记录加载与搜索时间；不要污染真实数据库。对比每键搜索和 250ms 防抖，再比较内存过滤与 SQL 条件查询。为日志设置最大行数，重复一千次追加后确认旧行被移除。

验收：每项优化有修改前后同条件数据；正确性测试仍通过；无法实测的平台标注清楚。不要为了快而删除错误检查，也不要把“不再重绘”当作界面优化成功。
