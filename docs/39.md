# 39 · 性能与内存：先测量，再优化

**前置**：第 21、27、38 章。**目标**：找到真正耗时的位置，并区分慢、阻塞和泄漏。

## 四类问题不要混在一起

启动慢可能来自大量读取和初始化；界面卡顿常是 GUI 线程长任务；内存上升可能来自缓存或未结束的请求；数据库慢可能是全表扫描。先描述观察到的现象、数据量和耗时，再决定工具。

```cpp
QElapsedTimer timer;
timer.start();
// 在这里执行一次待测操作，例如加载 10000 条测试记录。
qInfo() << "加载耗时(ms):" << timer.elapsed();
```

记录机器、构建配置、数据量、冷启动或热启动。Debug 的耗时不能直接代表 Release。微秒级操作容易受系统调度影响，不把一次测量当作绝对结论；涉及事件循环的总耗时还应包括异步完成时刻。

## 优先处理数量级

每次按键遍历十万行，比一次 QString 拷贝更值得关注。数据库筛选下推 SQL、按需加载、合并进度信号、批量更新模型，通常比手工优化小表达式更有效。大量表格行使用模型与委托，不创建十万个 QWidget。

设置定时器 1ms 不保证一秒回调一千次，忙时可能延迟；反复 processEvents 可能引入重入，不能当作性能方案。异步化也不一定使总计算更快，它首先改善界面响应，并可能增加同步成本。

## 内存所有权检查

检查无父对象的堆 QObject、未 deleteLater 的网络 reply、不断增长的日志、未消费的 queued 信号。QPointer 观察销毁，不释放对象；shared_ptr 引用环不会因窗口关闭自动消失。缓存应说明容量和淘汰策略。

任务管理器中的进程内存不立即下降，不足以证明泄漏；分配器和缓存可能保留内存。用重复执行后的稳定趋势、对象计数和合适的分析器进一步判断，不凭一张截图下结论。

## 动手实验

为 TaskDesk 的副本生成 100、10000、50000 条测试任务，记录加载与搜索时间；不要污染真实数据库。对比每键搜索和 250ms 防抖，再比较内存过滤与 SQL 条件查询。为日志设置最大行数，重复一千次追加后确认旧行被移除。

验收：每项优化有修改前后同条件数据；正确性测试仍通过；无法实测的平台标注清楚。不要为了快而删除错误检查，也不要把“不再重绘”当作界面优化成功。

参考：[QElapsedTimer](https://doc.qt.io/qt-6.8/qelapsedtimer.html)、[Qt Quick 性能](https://doc.qt.io/qt-6.8/qtquick-performance.html)。

## QML、测试与工程诊断：参数、结果与时机

### `QQmlApplicationEngine::loadFromModule(uri, typeName)`

- **参数怎样填**：课程使用 Course 与 Main。
- **作用与返回结果**：加载模块中的根类型，返回 void。
- **调用时机与易错点**：配置 URI、资源名或 required 属性错误会使创建失败，连接 objectCreationFailed 处理退出。

### `Q_PROPERTY(... READ ... NOTIFY ...)`

- **参数怎样填**：这是元对象声明宏，不是运行时函数。
- **作用与返回结果**：使属性可被读取并通知变化。
- **调用时机与易错点**：NOTIFY 的发送必须由你的代码保证；getter 不应执行长时间磁盘或网络工作。

### `Counter::increment()`

- **参数怎样填**：课程自定义 Q_INVOKABLE，无参数。
- **作用与返回结果**：改变 count 并发 countChanged。
- **调用时机与易错点**：Q_INVOKABLE 只暴露调用能力，不自动启动线程。

### `QSignalSpy(sender, signal)`

- **参数怎样填**：被观察对象和信号指针。
- **作用与返回结果**：创建信号记录器，用 isValid 检查。
- **调用时机与易错点**：尽量在动作前创建，以免错过已经同步发出的信号。

### `QSignalSpy::wait(timeout)`

- **参数怎样填**：最长等待毫秒数。
- **作用与返回结果**：在超时内收到新信号返回 true。
- **调用时机与易错点**：先检查已有数量再 wait，避免信号已发生却继续等待下一次。

### `QVERIFY(expr) / QCOMPARE(actual, expected)`

- **参数怎样填**：测试条件或实际值与期望值。
- **作用与返回结果**：失败记录上下文并结束当前测试函数。
- **调用时机与易错点**：它们是测试宏，不是给真实用户处理错误的界面。

### `QTRY_VERIFY(expr) / QTRY_COMPARE(actual, expected)`

- **参数怎样填**：可在事件循环中逐步成立的条件。
- **作用与返回结果**：重试直到成立或超时。
- **调用时机与易错点**：不是无限等待；比固定 sleep 更能适应不同机器速度。

### `QTest::mouseClick(widget, button)`

- **参数怎样填**：控件与鼠标按钮等参数。
- **作用与返回结果**：模拟交互。
- **调用时机与易错点**：应测真实窗口的用户结果，而不是仅证明 Qt 自带按钮能发信号。

### `QLoggingCategory(...) / qCWarning(category)`

- **参数怎样填**：日志分类和输出表达式。
- **作用与返回结果**：按类别组织诊断。
- **调用时机与易错点**：不会自动写日志文件、轮转或删除敏感信息，仍需明确日志策略。

### `QProcess 等外部工具`

- **参数怎样填**：本课程部署脚本实际调用 windeployqt，而非此处启动 Qt 类。
- **作用与返回结果**：部署命令收集 DLL、插件和 QML。
- **调用时机与易错点**：工具返回成功不证明所有 GPU、驱动、用户输入路径和第三方许可均已验收。

**阅读任务**：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 [完整函数手册](API.md#qmltest) 继续查阅。
