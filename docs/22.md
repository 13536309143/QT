# 22 · 代理模型、选择、委托与分页

## 代理模型改变展示顺序
QSortFilterProxyModel 位于原模型与视图之间，负责排序和筛选。代理第 0 行不一定是源模型第 0 行。对业务数据进行修改或删除时，必须 `mapToSource`，再读取稳定主键操作数据库。
```cpp
QModelIndex source = proxy->mapToSource(table->currentIndex());
if (!source.isValid()) return;
int id = model->data(model->index(source.row(), 0)).toInt();
```
TaskDesk 采用这个流程，防止搜索后删除错误任务。用户清除搜索文本后，原数据还在，因为过滤只改变显示范围，不删除源数据。

## 委托与大数据
默认委托能编辑常见类型。对于优先级可继承 QStyledItemDelegate，实现 createEditor、setEditorData、setModelData，提供 QComboBox 或 QSpinBox。不要在每个 cell 上 setIndexWidget 来替代正常委托。

数据库模型可能分批 fetchMore；rowCount 未必是数据库总行数。本课程 TaskDesk 的状态栏写“已载入”，而不是声称精确总数。大数据中内存代理过滤只能覆盖已载入行，应把筛选条件下推到 SQL，并加 LIMIT/OFFSET 或基于主键的分页；查询参数仍要绑定。

练习：先创建十条任务，排序、搜索后删除其中一条，确认真正删除的是该主键。验收：无选择时不操作；筛选后删除没有误删；翻页与搜索状态能清楚展示。进阶：把“完成”列改为可勾选显示，而不是 1/0，业务修改仍走仓储接口。
