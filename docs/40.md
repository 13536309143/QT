# 40 · Windows 部署：让程序离开开发机

## SDK 与应用分发包是两回事
SDK 包含头文件、导入库和开发工具，供编译使用；dist 包含 exe 和运行需要的 DLL、插件与 QML 模块，供用户运行。不能把整个 sdk 上传到 GitHub，也不能只发一个依赖动态 Qt 的 exe。

使用项目脚本：
```powershell
scripts\deploy.cmd 01_hello
scripts\deploy.cmd taskdesk
scripts\deploy.cmd 13_quick
```
脚本从 Release 输出复制指定程序，再调用同一 SDK 的 windeployqt；Quick 应额外传入 --qmldir 扫描 QML 源码。SQL 程序要检查 sqldrivers/qsqlite.dll，Widgets 程序需要 platforms/qwindows.dll。编译器运行库也应由合法方式分发。脚本会将 vc_redist.x64.exe 放入分发目录，目标机器缺少 MSVC 运行库时先安装，再运行应用。

## 干净环境验证
在没有 Qt PATH 的终端或干净 Windows 虚拟机运行 dist 程序，检查打开、保存、中文路径、数据库和关闭流程。使用独立分发目录避免“开发机 PATH 帮你找到缺失依赖”产生假成功。图形驱动、TLS 后端和 Windows 系统版本也可能影响运行，不能仅凭 windeployqt 返回成功就宣称适配所有电脑。

Debug 与 Release DLL 不混用，MSVC 与 MinGW 不混用，不同 Qt 版本尽量不混用。需要安装包时再选择合适工具，本课程先提供可检查的目录式分发。

练习：分别部署 hello 和 Quick，比较目录差异。验收：分发包可以从另一个目录启动；即使原源码不在也能找到静态资源。发布前核对实际依赖模块许可，并提供对应通知和合规材料；仓库自己的 LICENSE 不会替代第三方依赖许可。
参考：[Windows 部署](https://doc.qt.io/qt-6.8/windows-deployment.html)、[Qt 许可说明](https://doc.qt.io/qt-6.8/licensing.html)。

## QML、测试与工程诊断：参数、结果与时机

### `QQmlApplicationEngine::loadFromModule(uri, typeName)`

- **参数怎样填**：课程使用 Course 与 Main。
- **作用与返回结果**：加载模块中的根类型，返回 void。
- **调用时机与易错点**：配置 URI、资源名或 required 属性错误会使创建失败，连接 objectCreationFailed 处理退出。

### `Q_PROPERTY(... READ ... NOTIFY ...)`

- **参数怎样填**：这是元对象声明宏，不是运行时函数。
- **作用与返回结果**：使属性可被读取并通知变化。
- **调用时机与易错点**：NOTIFY 的发送必须由你的代码保证；getter 不应执行长时间磁盘或网络工作。

### `Counter::increment()`

- **参数怎样填**：课程自定义 Q_INVOKABLE，无参数。
- **作用与返回结果**：改变 count 并发 countChanged。
- **调用时机与易错点**：Q_INVOKABLE 只暴露调用能力，不自动启动线程。

### `QSignalSpy(sender, signal)`

- **参数怎样填**：被观察对象和信号指针。
- **作用与返回结果**：创建信号记录器，用 isValid 检查。
- **调用时机与易错点**：尽量在动作前创建，以免错过已经同步发出的信号。

### `QSignalSpy::wait(timeout)`

- **参数怎样填**：最长等待毫秒数。
- **作用与返回结果**：在超时内收到新信号返回 true。
- **调用时机与易错点**：先检查已有数量再 wait，避免信号已发生却继续等待下一次。

### `QVERIFY(expr) / QCOMPARE(actual, expected)`

- **参数怎样填**：测试条件或实际值与期望值。
- **作用与返回结果**：失败记录上下文并结束当前测试函数。
- **调用时机与易错点**：它们是测试宏，不是给真实用户处理错误的界面。

### `QTRY_VERIFY(expr) / QTRY_COMPARE(actual, expected)`

- **参数怎样填**：可在事件循环中逐步成立的条件。
- **作用与返回结果**：重试直到成立或超时。
- **调用时机与易错点**：不是无限等待；比固定 sleep 更能适应不同机器速度。

### `QTest::mouseClick(widget, button)`

- **参数怎样填**：控件与鼠标按钮等参数。
- **作用与返回结果**：模拟交互。
- **调用时机与易错点**：应测真实窗口的用户结果，而不是仅证明 Qt 自带按钮能发信号。

### `QLoggingCategory(...) / qCWarning(category)`

- **参数怎样填**：日志分类和输出表达式。
- **作用与返回结果**：按类别组织诊断。
- **调用时机与易错点**：不会自动写日志文件、轮转或删除敏感信息，仍需明确日志策略。

### `QProcess 等外部工具`

- **参数怎样填**：本课程部署脚本实际调用 windeployqt，而非此处启动 Qt 类。
- **作用与返回结果**：部署命令收集 DLL、插件和 QML。
- **调用时机与易错点**：工具返回成功不证明所有 GPU、驱动、用户输入路径和第三方许可均已验收。

**阅读任务**：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 [完整函数手册](API.md#qmltest) 继续查阅。
