# 29 · HTTP 网络：异步、超时和错误分层

## 建立可重复实验
在项目根目录开一个终端运行：
```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory examples/09_http
```
另一个终端启动 09_http，点击 GET，应该看到 HTTP 200 和 sample.json 的中文内容。本地服务器无需外部服务或 API 密钥。关闭服务器后再点一次，观察连接失败。换成不存在路径，观察 404。用完 Ctrl+C 结束服务器。

QNetworkAccessManager 可以长期复用，reply 表示一次请求。finished 时读取结果，再 deleteLater。异步回调给窗口上下文，避免窗口销毁后继续更新已经不存在的控件。本示例将窗口作为 manager 父对象，窗口关闭时请求对象一并清理。

## 不只检查一个错误
网络连通、TLS、HTTP 状态、JSON 格式和业务字段是不同层级。状态码成功不代表 body 一定是你需要的 JSON。setTransferTimeout 设置无数据超时，示例还用定时器设置总时限，并限制响应规模；downloadProgress 的限制只是教学级防护，生产下载应在 readyRead 中边收边限制/落盘。

不要 ignoreSslErrors 解决证书问题；应检查系统时钟、证书链、服务端配置和 Qt TLS 后端。日志不要记录 Authorization 等凭据。自动重试要考虑幂等性：GET 的重试和创建订单 POST 的重试不能同样处理。

练习：成功返回后解析 JSON 并展示 message；解析失败保留原始错误。验收：重复点击不会发起无限并行请求，服务器关闭与 404 都能恢复按钮，窗口能在请求中关闭。
参考：[QNetworkAccessManager](https://doc.qt.io/qt-6.8/qnetworkaccessmanager.html)。

## 配套完整源码

在根工程构建本章目标：`09_http`。以下是仓库内同一份文件，修改请到 examples 目录。

### main.cpp

```cpp
#include <QtWidgets>
#include <QtNetwork>
int main(int argc,char **argv) {
    QApplication app(argc,argv); QWidget w; auto *layout=new QVBoxLayout(&w);
    auto *url=new QLineEdit("http://127.0.0.1:8765/sample.json",&w);
    auto *button=new QPushButton(QStringLiteral("GET 请求"),&w);
    auto *output=new QPlainTextEdit(&w); output->setReadOnly(true);
    auto *manager=new QNetworkAccessManager(&w);
    layout->addWidget(url); layout->addWidget(button); layout->addWidget(output);
    QObject::connect(button,&QPushButton::clicked,&w,[url,button,output,manager,&w] {
        QUrl target(url->text());
        if(!target.isValid() || (target.scheme()!="https" && target.scheme()!="http") || target.host().isEmpty()) {
            output->setPlainText(QStringLiteral("请输入有效 HTTP/HTTPS 地址")); return;
        }
        button->setEnabled(false); output->clear();
        QNetworkRequest request(target); request.setTransferTimeout(10000);
        auto *reply=manager->get(request);
        // 总时限独立于“连续无数据”超时；reply 销毁时定时器自动失效。
        QTimer::singleShot(15000,reply,[reply] { if(reply->isRunning()) reply->abort(); });
        QObject::connect(reply,&QNetworkReply::downloadProgress,reply,[reply](qint64 received,qint64) {
            if(received>1024*1024) reply->abort(); // 教学客户端限制为 1 MiB
        });
        QObject::connect(reply,&QNetworkReply::finished,&w,[reply,button,output] {
            const auto status=reply->attribute(QNetworkRequest::HttpStatusCodeAttribute).toInt();
            output->setPlainText(QStringLiteral("HTTP %1\n%2\n%3").arg(status)
                .arg(reply->error()==QNetworkReply::NoError?QStringLiteral("成功"):reply->errorString())
                .arg(QString::fromUtf8(reply->readAll())));
            reply->deleteLater(); button->setEnabled(true);
        });
    });
    w.resize(700,450); w.show();
    if(app.arguments().contains("--smoke")) QTimer::singleShot(150,&app,&QCoreApplication::quit);
    return app.exec();
}
```

## 线程、HTTP 与 TCP：参数、结果与时机

### `QThread::start() / isRunning()`

- **参数怎样填**：启动可指定优先级；查询无参数。
- **作用与返回结果**：启动线程 / 返回 bool。
- **调用时机与易错点**：线程开始不等于业务已经完成；重复点击前检查实际状态。

### `requestInterruption() / isInterruptionRequested()`

- **参数怎样填**：无参数。
- **作用与返回结果**：发协作取消请求 / 查询 bool。
- **调用时机与易错点**：请求不会强杀线程，工作代码需周期检查，阻塞操作还需有界超时。

### `QThread::quit() / wait()`

- **参数怎样填**：请求事件循环结束 / 可指定等待上限。
- **作用与返回结果**：quit 返回 void，wait 返回 bool。
- **调用时机与易错点**：quit 不会中断正在执行的长循环；GUI 上长时间 wait 会冻结界面。

### `QNetworkAccessManager::get(request)`

- **参数怎样填**：QNetworkRequest。
- **作用与返回结果**：返回 QNetworkReply 指针，网络异步继续。
- **调用时机与易错点**：调用返回不是请求完成；reply 生命周期与 finished/error 处理必须清楚。

### `QNetworkRequest::setTransferTimeout(ms)`

- **参数怎样填**：无数据传输超时毫秒数。
- **作用与返回结果**：设置传输超时策略。
- **调用时机与易错点**：不等同于所有情况下的总时限；课程另外设 singleShot 总时限。

### `QNetworkReply::attribute(code)`

- **参数怎样填**：如 HttpStatusCodeAttribute。
- **作用与返回结果**：返回 QVariant 状态信息。
- **调用时机与易错点**：无 HTTP 响应时可能没有状态码，不能把 0 当作正常 HTTP 状态。

### `QNetworkReply::error() / abort()`

- **参数怎样填**：查询或主动终止。
- **作用与返回结果**：返回错误枚举 / void。
- **调用时机与易错点**：abort 也会进入结束路径；恢复按钮和释放 reply 不应只写在成功分支。

### `QTcpServer::listen(address, port)`

- **参数怎样填**：监听地址和端口；0 请求系统分配。
- **作用与返回结果**：返回 bool；成功后用 serverPort 取实际端口。
- **调用时机与易错点**：本例只用 LocalHost；不要无意改为 Any 后把教学服务开放给局域网。

### `nextPendingConnection()`

- **参数怎样填**：无参数。
- **作用与返回结果**：返回待处理服务端 socket 指针。
- **调用时机与易错点**：在 newConnection 后处理；为每条连接保留独立解析器，并在断开后销毁。

### `QTcpSocket::connectToHost(address, port)`

- **参数怎样填**：地址与端口。
- **作用与返回结果**：启动异步连接，返回 void。
- **调用时机与易错点**：等待 connected 或 errorOccurred；不要在 GUI 中 waitForConnected 阻塞。

### `bytesAvailable() / read(maxSize)`

- **参数怎样填**：可读字节数查询或最大读取量。
- **作用与返回结果**：返回 qint64 / QByteArray。
- **调用时机与易错点**：一次读取不保证整帧，解析器必须保存尾部残留数据。

### `setReadBufferSize(bytes)`

- **参数怎样填**：最大接收缓冲字节数，0 有无限制语义。
- **作用与返回结果**：限制 socket 接收缓冲。
- **调用时机与易错点**：业务拆帧缓存、发送队列和日志也需分别设上限。

### `LineProtocol::feed(bytes, lines)`

- **参数怎样填**：自定义解析器；输入字节和输出完整行列表。
- **作用与返回结果**：返回 bool，false 表示超过帧上限。
- **调用时机与易错点**：按 LF 取帧，残留半帧保存在内部；false 时调用方终止连接，不把损坏数据当正常消息。

**阅读任务**：在本章源码中找到上述实际出现的调用，给每个返回值标出检查位置；同组的扩展接口用于对照，不要求在当前示例中全部出现。结合 [完整函数手册](API.md#async) 继续查阅。
