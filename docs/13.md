# 13 · 多窗口与对话框：确认、取消和对象寿命

**前置**：第 08、12 章。**目标**：创建第二个窗口，并正确处理取消和重复打开。

## 先选择窗口关系

| 类型 | 适合场景 | 关键问题 |
|---|---|---|
| 主窗口 | 主工具与菜单 | 谁是 centralWidget |
| 模态对话框 | 当前操作需要先做决定 | 取消是否保持原数据 |
| 非模态工具窗 | 查找、帮助、持续观察 | 关闭后是隐藏还是销毁 |

模态限制用户与其他窗口交互，不等于把工作放到后台。exec() 会建立嵌套事件循环，代码看起来像同步等待，但其他事件仍可能发生；新代码优先考虑 open() 配合 finished 或 accepted 信号。

## 一次性对话框的安全写法

以下片段放在 QWidget 子类成员函数中，`this` 是拥有者，已包含 QtWidgets：

```cpp
auto *dialog = new QDialog(this);
dialog->setWindowTitle(tr("修改姓名"));
dialog->setAttribute(Qt::WA_DeleteOnClose);
auto *layout = new QVBoxLayout(dialog);
auto *edit = new QLineEdit(dialog);
auto *buttons = new QDialogButtonBox(
    QDialogButtonBox::Ok | QDialogButtonBox::Cancel, dialog);
layout->addWidget(edit);
layout->addWidget(buttons);
connect(buttons, &QDialogButtonBox::accepted, dialog, &QDialog::accept);
connect(buttons, &QDialogButtonBox::rejected, dialog, &QDialog::reject);
connect(dialog, &QDialog::accepted, this, [this, edit] {
    setWindowTitle(edit->text().trimmed());
});
dialog->open();
```

数据在 accepted 时才提交，Cancel 不改变主窗口。真实表单应先验证再 accept；上例只用于理解窗口寿命和信号顺序，不代表完整的姓名业务规则。

## 两个常见错误

在函数中创建局部 `QDialog dialog; dialog.open();` 后立即返回，对话框随局部变量析构，不能继续显示。反过来，不断 new 顶层窗口却没有父对象、也不设置关闭后删除，会残留隐藏对象。

需要始终只开一个查找窗时，将其保存在 QPointer 成员中；存在则 show、raise、activateWindow，不存在再创建。QPointer 在销毁后清空，但隐藏不会清空。应先决定“复用隐藏窗口”还是“关闭即删除”，再选择逻辑。

## 动手与验收

给 03_form 增加一个“修改姓名”按钮。先允许连续打开多个窗口，观察各自状态；再实现单实例。测试确定、Cancel、右上角关闭、主窗口先关闭四条路径。

参考答案要点：临时输入放在对话框内，业务数据在确认后改变；引用捕获的局部变量不能随函数返回而消失。验收：Cancel 保持原姓名，连续打开不产生悬空访问，主窗口关闭后子窗口正确清理。
